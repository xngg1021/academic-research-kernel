# academic-research-kernel (hi)

[English](../../README.md) · [简体中文](../../README.zh-Hans.md) · [繁體中文](../../README.zh-Hant.md) · [日本語](../../README.ja.md) · [한국어](../../README.ko.md) · [Deutsch](../../README.de.md) · [Français](../../README.fr.md) · [Español](../../README.es.md) · [Português](../pt/README.md) · [Русский](../ru/README.md) · [Bahasa Indonesia](../id/README.md) · [Italiano](../it/README.md) · [हिन्दी](../hi/README.md) · [العربية](../ar/README.md) · [বাংলা](../bn/README.md) · [اردو](../ur/README.md) · [Tiếng Việt](../vi/README.md) · [Türkçe](../tr/README.md) · [فارسی](../fa/README.md) · [Kiswahili](../sw/README.md) · [Polski](../pl/README.md)

एजेंट-आधारित शोध कार्यप्रवाहों के लिए प्लेटफ़ॉर्म-स्वतंत्र और नियतात्मक (deterministic) अकादमिक अनुसंधान स्थिति प्रबंधन प्रणाली। यह प्रणाली अनुसंधान कलाकृतियों का अंतर्ग्रहण करने वाले नियतात्मक सेतु और सार्वभौमिक Model Context Protocol (MCP) सर्वर के माध्यम से अनुसंधान वस्तु की पहचान, अनुभवजन्य साक्ष्य / सत्यापन रिकॉर्ड, त्रिपक्षीय दावा-साक्ष्य संबंध (CEG) तथा केवल-जोड़ने योग्य अनुसंधान निर्णय और नकारात्मक परिणाम लॉग को एकीकृत करती है। 14 विशेषीकृत अकादमिक कौशल सत्यापित अनुसंधान स्थिति के उत्पादक और उपभोक्ता दोनों के रूप में कार्य करते हैं, तथा Claude Code, Cursor, Codex, Gemini CLI और Hermes Agent को मूल समर्थन प्रदान करते हैं। सत्यापन का दायरा और बाहरी सेवाओं की सीमाएं [ऑडिट दस्तावेज़](../../docs/kernel-architecture.md) में दर्ज हैं।

लेखक: Junfu Shi (SJF, xngg1021), Hermes Agent। वर्तमान लाइसेंस प्रस्ताव: [Source Lineage License 1.0](../../LICENSE)।

## त्वरित शुरुआत

[uv](https://docs.astral.sh/uv/getting-started/installation/) के साथ संस्करण 2.2.0 चलाएं:

```bash
uvx academic-research-kernel@2.2.0 mcp
```

[2.2.0 रिलीज़](https://github.com/xngg1021/academic-research-kernel/releases/tag/v2.2.0) वितरण हैश और प्रकाशन स्थिति को रिकॉर्ड करता है। रिलीज़ व्हील को स्थानीय रूप से `uvx --from ./academic_research_kernel-2.2.0-py3-none-any.whl academic-research-kernel mcp` के माध्यम से भी चलाया जा सकता है। Python 3.10–3.14 समर्थित है; `uvx --python 3.12` स्पष्ट रूप से समर्थित इंटरप्रेटर का चयन करता है। वैज्ञानिक गणना और सांख्यिकी उपकरण सहित सभी 12 नियतात्मक उपकरण मूल इंस्टॉलेशन में शामिल हैं।

## इंस्टॉलेशन की जांच करें

```bash
uvx academic-research-kernel@2.2.0 doctor
uvx academic-research-kernel@2.2.0 --version
```

ऑफ़लाइन डायग्नोस्टिक निर्भरताओं, स्कीमा और सभी 12 टूल परिभाषाओं की जांच करता है। वैकल्पिक बाहरी सेवाएं बिना कॉन्फ़िगर किए रह सकती हैं। मशीन-पठनीय आउटपुट के लिए `doctor --json` का उपयोग करें।

## पैकेज इंस्टॉलेशन

```bash
uv tool install academic-research-kernel==2.2.0
academic-research-kernel doctor
academic-research-kernel mcp
```

वैकल्पिक रूप से, समर्थित वर्चुअल एनवायरनमेंट के भीतर `pipx install academic-research-kernel==2.2.0` या `python -m pip install academic-research-kernel==2.2.0` के साथ इंस्टॉल करें। `[full]` विस्तारित वैज्ञानिक कौशल उदाहरणों के लिए लाइब्रेरी जोड़ता है; `[qa]` पीडीएफ पार्सर सहित रिपॉजिटरी सत्यापन उपकरण जोड़ता है। `[research]` स्वच्छ इंस्टॉलेशन में सुसंगत पीडीएफ फ़ॉन्ट डिकोडिंग के लिए `pypdf==6.19.0` और `fonttools==4.65.0` जोड़ता है; दोनों Python 3.10 का समर्थन करते हैं। संरचित HTML/XML और सीमित आकार के DOCX/XLSX पठन के लिए मानक लाइब्रेरी का उपयोग किया जाता है। GPU बैकएंड और सशुल्क सेवाएं वैकल्पिक रहती हैं।

## Hermes

uv को इस प्रकार इंस्टॉल करें कि वह Hermes प्रक्रिया के PATH में उपलब्ध हो, फिर पोर्टेबल प्लगइन को इंस्टॉल और स्पष्ट रूप से सक्षम करें:

```bash
hermes plugins install xngg1021/academic-research-kernel --no-enable
hermes plugins enable academic-skills
```

मौजूदा `academic-skills` पहचान को बनाए रखा गया है, जिसमें अब `paper-research` सहित 14 कौशल शामिल हैं। प्लगइन का `mcp.json` Python 3.12 और चेकआउट के `uv.lock` के साथ `uv run --frozen --no-dev --no-editable` को कॉल करता है; इसका रनटाइम वातावरण `${PLUGIN_DATA}/runtime` के अंतर्गत रहता है। यह Hermes या सिस्टम के Python पैकेजों को उधार लिए बिना, पहले उपयोग पर निर्भरताओं को स्वतः स्थापित करता है। अनुपस्थित पैकेज या इंटरप्रेटर प्राप्त करने के लिए पहले उपयोग के समय नेटवर्क एक्सेस की आवश्यकता होती है। केवल-कौशल वाला पुराना टैप तरीका नीचे एकीकरण और पोर्टेबल उपयोग अनुभाग में समर्थित है।

## स्रोत कोड से चलाएं

```bash
git clone https://github.com/xngg1021/academic-research-kernel.git
cd academic-research-kernel
uv sync --frozen --no-dev --no-editable
uv run --frozen --no-dev --no-editable academic-research-kernel doctor

निर्भरता वर्गीकरण, पुनरुत्पादन चरणों, रिलीज़ पहचान, प्रकाशन जांच-बिंदुओं और सत्यापन दायरे के लिए [वितरण और रिलीज़ दस्तावेज़](../../docs/distribution-release.md) देखें।

## अकादमिक मानक और बहु-प्रोफ़ाइल आधार रेखा

उद्धरण शैलियाँ, रिपोर्टिंग मानदंड और मेटाडेटा अनुबंध लक्षित जर्नल, संस्थान, वित्तपोषक, अनुशासन और न्यायक्षेत्र पर निर्भर करते हैं। रिपॉजिटरी अंतरराष्ट्रीय आधार रेखा के रूप में **ISO 690:2021** (ग्रंथसूची संदर्भ), **ISO 5127:2017** (सूचना और प्रलेखन शब्दावली) और **W3C PROV** (उत्पत्ति डेटा मॉडल) को स्थापित करती है, जिसके साथ क्षेत्रीय प्रोफाइल (जैसे मुख्यभूमि चीन में GB/T 7714-2025, स्पेन में UNE-ISO 690:2024, जर्मनी में DIN ISO 690:2021) और अनुशासनात्मक मानक (APA 7th, IEEE, ACM, Vancouver, Chicago, PRISMA 2020, ICMJE) शामिल हैं। लक्षित प्रकाशन स्थल की आवश्यकताएं डिफ़ॉल्ट प्रोफाइल पर प्राथमिकता रखती हैं। [अकादमिक मानक वास्तुकला](../../docs/standards/README.md) और [प्राकृतिक शब्दावली गाइड](../../docs/terminology/README.md) देखें।

अंतिम कर्नेल सत्यापन सुधार DOI/पहचानकर्ता सुसंगतता, पारस्परिक रूप से अनन्य मात्रात्मक निर्णय फ़्लैग और साझा कर्नेल/रसीद समीक्षा की आवश्यकता वाले बिंदु अनुबंध को मान्य करता है। कैश पूर्णता को रसीद की उत्परिवर्तन सूचियों से स्वतंत्र रूप से, प्रतिधारित स्रोत लिफाफों और सामान्यीकृत बाइंडिंग से पुनर्निर्मित किया जाता है; किसी रिकॉर्ड और उसकी कैश घोषणा दोनों को हटाने से स्वीकृत रीप्ले उत्पन्न नहीं हो सकता। [चार-अवरोधक समापन रिपोर्ट](../../docs/kernel-architecture.md) देखें।

# Add as stdio MCP server in your agent harness
uvx academic-research-kernel mcp
```

### 2. Hermes में मूल इंस्टॉलेशन
Hermes इंस्टॉलेशन वातावरण से निम्नलिखित चलाएं:

```bash
hermes skills tap add xngg1021/academic-research-kernel
hermes skills search academic-source-verification
hermes skills install xngg1021/academic-research-kernel/skills/academic-source-verification
```

पूर्ण पहचानकर्ता में निर्देशिका नाम बदलकर अन्य कौशल इंस्टॉल करें। एक सामान्य टैप डिफ़ॉल्ट शाखा को पढ़ता है, इसलिए नया टैप ऊपर दी गई कौशल सूची को इंस्टॉल करता है। मर्ज से पहले किसी कार्यशील शाखा का निरीक्षण करने के लिए, उस शाखा को स्थानीय रूप से चेक आउट करें और इंस्टॉल किए गए Hermes संस्करण के स्थानीय-फ़ोल्डर इंस्टॉलेशन निर्देशों का पालन करें। यह मानकर न चलें कि टैप कमांड किसी पुल रिक्वेस्ट शाखा का चयन करता है।

अपस्ट्रीम कमिट `245e48008fa814b3251f50755eb656bd9fb86cb1` पर जांचे गए संबंधित बंडल कौशल: arxiv, grounded-citations, docx, pdf, manim-video। huggingface-hub और llama-cpp वैकल्पिक कैटलॉग में हैं और उन्हें अलग से इंस्टॉल करने की आवश्यकता हो सकती है। ocr-and-documents और pc-hardware-benchmark उस स्नैपशॉट में नहीं मिले और वे निर्भरताएं नहीं हैं। सत्र उपकरण तथा दस्तावेज़/ब्राउज़र बैकएंड स्थानीय कॉन्फ़िगरेशन पर निर्भर करते हैं।

## डेटा-स्रोत पहुंच

- OpenAlex की बुनियादी क्वेरी छोटे दैनिक बजट के साथ अनाम रूप से चल सकती हैं। 2026-09-06 के दस्तावेज़ों के अनुसार अनाम रूप से $0.10/दिन और निःशुल्क API कुंजी के साथ $1/दिन का बजट तथा 100 अनुरोध/सेकंड की सीमा निर्धारित है। क्वेरी प्रकार के अनुसार लागत भिन्न होती है; यह असीमित पहुंच नहीं है। वैकल्पिक कुंजी को `OPENALEX_API_KEY` में संग्रहीत करें। `per_page` (अधिकतम 100) और कर्सर पेजिनेशन का उपयोग करें।
- Crossref थ्रॉटलिंग के साथ सार्वजनिक मेटाडेटा पहुंच प्रदान करता है। अद्यतन संबंधों और Retraction Watch संकेतों के लिए DOI और दिशा की जांच आवश्यक है; रिकॉर्ड का न मिलना यह सिद्ध नहीं करता कि शोध-पत्र अप्रभावित है।
- Unpaywall के लिए `UNPAYWALL_EMAIL` में एक वास्तविक संपर्क ईमेल आवश्यक है। किसी स्थान का न मिलना यह सिद्ध नहीं करता कि कोई ओपन एक्सेस (OA) प्रति मौजूद नहीं है।
- arXiv, Europe PMC, PubMed E-utilities और DOAJ अपनी स्वयं की नीतियों वाले पूरक स्रोत हैं। डिफ़ॉल्ट परीक्षणों द्वारा उन सभी का अभ्यास नहीं किया जाता है। Semantic Scholar में साझा अनाम सीमाएं और अलग से आवंटित कुंजी सीमाएं हैं; API पहुंच उद्धरण-संदर्भ की उपलब्धता की गारंटी नहीं देती है।
- Scite, Dimensions, Scopus, Web of Science और AI-पहचान उत्पाद वैकल्पिक बाहरी सेवाएं हैं। उपयोग से पहले वर्तमान खाता/API अधिकारों और कोटा की जांच करें; किसी सार्वभौमिक निःशुल्क स्तर या निश्चित मूल्य का वादा नहीं किया जाता है।

[OpenAlex प्रमाणीकरण](https://help.openalex.org/api/authentication/), [बजट और क्वेरी लागत](https://help.openalex.org/api/llm-quick-reference/), और [Crossref अद्यतन फ़िल्टर](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/) देखें।

## नियतात्मक अंतर्ग्रहण और सार्वजनिक कर्नेल

अनुसंधान कलाकृतियों का अंतर्ग्रहण परत `ResearchArtifactEnvelope v1`, `ArtifactIngestionReceipt v1`, 15 एडेप्टर (14 कौशल और एक अपारदर्शी फ़ॉलबैक opaque fallback), तथा 12 स्टेटलेस stdio MCP उपकरण प्रदान करती है। स्वीकृत अंतर्ग्रहण रसीदें प्रत्येक प्रतिधारित अर्थगत परिवर्तन को प्रकार, पहचान और कैननिकल SHA-256 द्वारा बांधती हैं: वस्तुएं, CEG रिकॉर्ड, निर्णय लॉग रिकॉर्ड, समीक्षा की आवश्यकता वाले बिंदु, भौतिक रसीदें और कलाकृति पंजीकरण। कैश रीप्ले ट्रांसपोर्ट स्नैपशॉट हैश से स्वतंत्र रूप से उन प्रतिबद्धताओं की जांच करता है। खाली लॉग मान्य हैं; विफल परमाणु बैच कोई आंशिक स्थिति नहीं छोड़ते।

वंशावली सामग्री प्राधिकार स्पष्ट और आउट-ऑफ-बैंड है। विश्वसनीय Python कॉलर क्रमबद्ध रसीदों या स्नैपशॉट को रीप्ले करते समय `LineageVerificationContext` पास करते हैं; MCP कॉलर केवल सीमित सामग्री बाइट्स की आपूर्ति कर सकते हैं, कभी भी होस्ट फ़ाइल सिस्टम रूट की नहीं। डिफ़ॉल्ट सामग्री बजट 10 MiB है; एक विश्वसनीय होस्ट समान उत्पादक/सत्यापनकर्ता नीति के तहत बड़ी कलाकृतियों को स्पष्ट रूप से अधिकृत कर सकता है। सामग्री प्राधिकार के बिना, `fully_verified` दावे को स्वतंत्र रूप से पुनरुत्पादित नहीं किया जा सकता है और यह एक संरचित अमान्य सत्यापन परिणाम लौटाता है। असंरचित गद्य अपारदर्शी रहता है, असहमति दृश्यमान रहती है, और शोधकर्ता कमिट, मार्ग रोकने, पुनः खोलने, रूटिंग और सत्यता निर्णयों पर नियंत्रण बनाए रखते हैं।

अनुबंधों और संगतता के लिए [कर्नेल वास्तुकला दस्तावेज़](../../docs/kernel-architecture.md) देखें। वितरण और प्रकाशन जांच-बिंदु [रिलीज़ गाइड](../../docs/distribution-release.md) में दर्ज हैं। अंग्रेज़ी और सरलीकृत चीनी README अद्यतन हैं; अन्य अनुवाद स्थितियाँ [सिंक्रनाइज़ेशन मैनिफेस्ट](../../docs/i18n/manifest.json) में स्पष्ट रूप से दर्ज हैं। अंतिम उम्मीदवार पहचान, सटीक-HEAD CI, संचयी समीक्षा और मर्ज साक्ष्य [समापन लेजर](https://github.com/xngg1021/academic-research-kernel/pull/12#issuecomment-5754741342) में दर्ज हैं।

## सत्यापन (Validation)

एक समर्पित Python वातावरण का उपयोग करें। रनटाइम लाइब्रेरी कार्य-विशिष्ट हैं और Hermes में पहले से इंस्टॉल होने की गारंटी नहीं है। QA निर्भरताएं अधिक व्यापक हैं ताकि सभी चिह्नित उदाहरण चल सकें:

```bash
python -m pip install -r requirements-qa.txt
python -m pip install 'torch>=2.5,<3' --index-url https://download.pytorch.org/whl/cpu
python scripts/qa.py
python -m pytest -q -rs tests
python scripts/i18n_sync.py --check
python scripts/verify_external_apis.py --output external-status.json --summary external-summary.md
git diff --check
```

QA मेटाडेटा, संदर्भ, व्यक्तिगत-पथ/ज्ञात-गुप्त पैटर्न, Python सिंटैक्स और चिह्नित निष्पादन योग्य कोड ब्लॉक को मान्य करता है। प्रत्येक स्मोक उदाहरण एक नई सबप्रोसेस में अपरिवर्तित रूप से चलता है। प्लॉट उदाहरण `PLOT_DIR` (डिफ़ॉल्ट `~/plots`, स्पष्ट रूप से विस्तारित) स्वीकार करते हैं; परीक्षण एक अस्थायी निर्देशिका का उपयोग करते हैं। अवर्गीकृत Python कोड ब्लॉक अस्वीकार कर दिए जाते हैं; `fragment:` ब्लॉक की सिंटैक्स जांच की जाती है लेकिन उन्हें नामित इनपुट की आवश्यकता होती है और उन्हें अकेले निष्पादित नहीं किया जाता है। `external-test:` ब्लॉक केवल मैन्युअल बाहरी कमांड के माध्यम से चलते हैं। यह कॉन्फ़िगर की गई जांच उत्तीर्ण होने पर 0, कोड/स्कीमा/पहचान विफलता पर 1, और ट्रांसपोर्ट/प्रमाणीकरण/कोटा अनुपलब्धता पर 2 लौटाता है; बिना कॉन्फ़िगर की गई वैकल्पिक सेवाएं SKIP रहती हैं।

पिन किए गए Hermes ऑथरिंग परीक्षणों को उनके प्रति-कौशल नियमों को बदले बिना पुनः उपयोग किया जाता है। अपस्ट्रीम संपूर्ण-वितरण जनसंख्या जांच इस टैप पर लागू नहीं होती; हमारा परीक्षण हार्नेस चौदह कौशलों की जांच करता है और पिन किए गए बंडल/वैकल्पिक कैटलॉग के विरुद्ध संदर्भों को हल करता है। यह पूर्ण Hermes इंस्टॉलेशन परीक्षण नहीं है। CI केवल निर्भरताएं इंस्टॉल करने के लिए नेटवर्क का उपयोग करता है; सामान्य परीक्षण अकादमिक API को कॉल नहीं करते हैं।

CI Linux x86_64 (Python 3.10–3.14), Linux ARM64 (ubuntu-24.04-arm), Ubuntu 26.04 प्रीव्यू कैनरी (ubuntu-26.04 और ubuntu-26.04-arm), Windows x86_64, Windows ARM64 (windows-11-arm), macOS ARM64 (macos-latest), और macOS Intel (macos-15-intel) पर लाइव अपस्ट्रीम कैनरी सत्यापन के साथ पूर्ण QA सूट चलाता है। आधारभूत रिलीज़ उम्मीदवार ने 1165 स्थानीय परीक्षण उत्तीर्ण किए। वर्तमान सुधार परिणाम और कवरेज सीमाएं [शुद्धता सुधार दस्तावेज़](../../docs/maintenance/correctness-repair-20261008.md) में दर्ज हैं; दूरस्थ साक्ष्य परीक्षण किए गए HEAD को अलग से पहचानता है। main पर पुश करने पर एक अलग टैप एकीकरण कार्यप्रवाह चलता है: यह `tests/upstream/provenance.json` में दर्ज पिन किए गए Hermes चेकआउट को इंस्टॉल करता है और इस रिपॉजिटरी के विरुद्ध `tap add`, `search`, `install` और `list` का अभ्यास करता है। सटीक संस्करण, जांच और सीमाएं [ऑडिट दस्तावेज़](../../docs/kernel-architecture.md) में हैं।

[tools/longtail/](../../tools/longtail/README.md) में नियतात्मक लॉन्ग-टेल कारक जनरेटर है: 4096 SHA256-सीडेड उम्मीदवार, 30 चयनित परिदृश्य और मशीन-गणना की गई सत्यापन कवरेज रिपोर्ट। v3 मॉडल क्षमता परिवारों (E01), रिपॉजिटरी के 14 वास्तविक कौशलों (E02), और कार्य लक्ष्यों (E03) की अलग-अलग गणना करता है। प्रत्येक परिदृश्य में एक प्राथमिक कौशल, एक समर्थित कार्य लक्ष्य और संगत क्षमताएं होती हैं; प्रत्येक कौशल को अपने घोषित मूल लक्ष्य सहित दो अलग-अलग लक्ष्यों के तहत कम से कम दो बार प्रकट होना चाहिए। कौशल-निर्देशिका विचलन होने पर सत्यापन विफल हो जाता है। अर्थगत विस्तार (कार्य श्रृंखला, ओरेकल और निष्पादित इवेंट इंजेक्शन) एक अलग चरण रहता है; कारक कवरेज कार्यप्रवाह निष्पादन कवरेज को सिद्ध नहीं करता है।

`scripts/scfabric/` वैज्ञानिक गणना और सांख्यिकी उपकरण का निष्पादन स्तर है: हार्डवेयर प्रोब, `dtype` गेट्स के साथ बैकएंड कैटलॉग, पांच वर्कलोड प्रोफाइल, समता प्रवेश के साथ युग्मित बेंचमार्क, और `ComputeReceipt`। इस मशीन पर पहले दौर के माप [docs/scientific-compute-fabric.md](../../docs/scientific-compute-fabric.md) में हैं; सामान्य नियम डिफ़ॉल्ट रूप से CPU का उपयोग करना है, और एक्सेलरेटर केवल रसीद के साथ ही सक्रिय किया जाता है।

## स्थानीय Agent के साथ शोध-पत्र का अध्ययन करें

`academic-research-kernel[research]==2.2.0` इंस्टॉल करें और पैकेज्ड कार्यप्रवाह निर्यात करें:

```sh
academic-research-kernel research skill --output ./agent-skills/paper-research
```

Work या किसी संगत स्थानीय Agent को उस निर्यातित `SKILL.md` को पढ़ने दें, फिर पूछें:
“研究这篇论文及其补充材料，整理方法，核对能重算的关键数字，给我一份带出处的中文报告。”
केवल DOI, सार्वजनिक लिंक या स्थानीय बंडल प्रदान करें। दो शोध-पत्रों के लिए, उसे डेटा, कार्यप्रणाली, मूल्यांकन शर्तों और परिणामों की तुलना करने के लिए कहें, यह स्पष्ट करते हुए कि किन परिणामों की सीधे तुलना की जा सकती है। Agent उसी कार्य में मूल-पाठ पठन, उम्मीदवार सत्यापन, गणना, अंतर्ग्रहण, रिपोर्ट निर्माण और स्वतंत्र सत्यापन और पुष्टि की प्रक्रिया को पूरा करता है। मौजूदा MCP सतह अपने 12 उपकरणों को बनाए रखती है; नया समन्वय CLI और पोर्टेबल कौशल में रहता है।

वास्तविक प्रोग्राम चरण इस प्रकार हैं:

```sh
academic-research-kernel research prepare INPUT --project PROJECT
academic-research-kernel research finish --project PROJECT --candidate CANDIDATE.json
academic-research-kernel research compare LEFT_PROJECT RIGHT_PROJECT --analysis COMPARISON.json --output OUTPUT
```

`prepare` सामग्री को प्राप्त करता है और उसे मैनिफेस्ट, स्रोत हैश और स्थानबद्ध खंडों में पार्स करता है। `finish` Agent द्वारा निर्मित निष्कर्षण को मान्य करता है और मौजूदा सांख्यिकीय उपकरणों का उपयोग करके पात्र t/p, दो-समूह प्रभाव-आकार और गणना/प्रतिशत दावों की पुनर्गणना करता है, फिर कर्नेल स्थिति और चीनी Markdown/HTML रिपोर्ट सहेजता है। `compare` तुलनीय शर्तों के बारे में Agent के स्पष्ट आकलन को मान्य करता है। ये कमांड किसी स्थायी मॉडल को एम्बेड नहीं करते हैं: अर्थगत पठन वर्तमान Agent द्वारा [paper-research](../../skills/paper-research/SKILL.md) का पालन करते हुए किया जाता है। सहेजी गई मूल फ़ाइलें और निष्कर्षण स्नैपशॉट नियतात्मक ऑफ़लाइन रीप्ले का समर्थन करते हैं। नेटवर्क अधिग्रहण और नया अर्थगत पठन अलग से पहचाने जाने वाले संचालन बने रहते हैं।

## 2.0.1 शुद्धता सुधार और वितरण सत्यापन

उत्पाद रिलीज़ 2.0.1 में सांख्यिकीय पुनर्गणना, शोध-पत्र वापसी ट्रैकिंग और MCP सत्र के शुद्धता सुधार शामिल हैं। सार्वजनिक `academic_recompute_statistics` टूल t-परीक्षण p-मान और दो-समूह Cohen's d / Hedges' g को उजागर करता है। विश्वास अंतराल (CI) और OR/RR निचले स्तर के Python फ़ंक्शन बने रहते हैं। जब रिपोर्ट की परिशुद्धता मायने रखती है तो `p_value_literal` (उदाहरण के लिए `"1.0e-5"`) या `p_value_decimals` प्रदान करें। लिटरल अंतिम शून्यों को सुरक्षित रखते हैं; संख्यात्मक इनपुट केवल अपने संख्यात्मक प्रतिनिधित्व को बनाए रखते हैं। परस्पर विरोधी परिशुद्धता स्रोत स्पष्ट रूप से विफल हो जाते हैं। राउंड-हाफ-अप तुलनाओं में निचली पूर्णांकन सीमा शामिल होती है और ऊपरी सीमा को बाहर रखा जाता है। एक सामान्य संख्यात्मक विसंगति एक सफल वैज्ञानिक परिणाम है; अमान्य या आंशिक रूप से विफल गणनाएं `isError` सेट करती हैं।

शोध-पत्र वापसी (retraction) जांच वर्तमान `True`/`False`/`unknown` अवलोकन को अंतिम-ज्ञात (`last-known`) मान से अलग रिकॉर्ड करती है। क्वेरी से पहले का एक संक्षिप्त आरक्षण समान-DOI अवलोकनों को क्रमबद्ध करता है और अन्य DOI अद्यतनों को सुरक्षित रखता है। वर्तमान अवलोकनों और ऐतिहासिक पुष्टियों के अलग-अलग संस्करण होते हैं: देर से मिली पुष्टि प्रतिधारित इतिहास को सुधार सकती है जबकि एक नया `unknown` वर्तमान जांच के लिए स्पष्ट रूप से असत्यापित रहता है। प्रतिगमन श्रृंखलाओं में HTTP फ़िक्स्चर को परीक्षण डेटा के रूप में लेबल किया गया है।

MCP `ping` का उत्तर देता है, मान्य सूचनाओं (`notifications/cancelled` सहित) के लिए शांत रहता है, और अमान्य इनपुट के बाद stdio सत्र को सक्रिय रखता है। सिंक्रोनस कार्यान्वयन प्रीएम्प्टिव रद्दीकरण का विज्ञापन नहीं करता है। संदेश प्रबंधन [MCP संदेश अनुबंध](https://modelcontextprotocol.io/specification/2024-11-05/basic/messages) और [ping विनिर्देश](https://modelcontextprotocol.io/specification/2024-11-05/basic/utilities/ping) का पालन करता है।

एक पृथक वातावरण के साथ इस चेकआउट के वितरणों को बनाएं और सत्यापित करें:

```bash
python -m build
python -m twine check --strict dist/*
python scripts/package_acceptance.py --dist dist --uvx --source-checks --report package-acceptance.json
```

`--source-checks` चेकआउट के बाहर उम्मीदवार `sdist` को अपरिवर्तित रूप से निकालता है, `ARK_REPO` और `ARK_SDIST` को उस उम्मीदवार पर सेट करता है, और उसके परीक्षण, स्थैतिक QA, निष्पादन योग्य कोड ब्लॉक और i18n जांच चलाता है। व्हील और `sdist` इंस्टॉलेशन प्रत्येक एक नए वातावरण का उपयोग करते हैं; `uvx` एक स्वतंत्र कैश के साथ स्थानीय व्हील का उपयोग करता है। रिपोर्ट कलाकृति हैश और इंस्टॉल किए गए इम्पोर्ट पथों को रिकॉर्ड करती है। शेड्यूल की गई हल्की पिन/नवीनतम Hermes जांच परीक्षण किए गए SHA को स्वतंत्र रूप से रिपोर्ट करती है। बाहरी अनुबंध JSON और जॉब सारांश `healthy`, `degraded` और `failed` का उपयोग करते हैं; छोड़े गए प्रोब स्पष्ट रहते हैं।
