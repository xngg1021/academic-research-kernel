سامانه و هسته قطعی مدیریت وضعیت پژوهش دانشگاهی برای جریان‌های کاری مبتنی بر عامل‌های هوشمند که مستقل از بستر اجرا عمل می‌کند. این چارچوب از طریق لایه قطعی ورود و تجزیه مصنوعات پژوهشی و سرور استاندارد پروتکل زمینه مدل (MCP)، شناسایی هویت موجودیت‌های پژوهشی، سند شواهد / راستی‌آزمایی تجربی، ارتباط میان ادعاها و شواهد (CEG) و دفتر ثبت تصمیمات پژوهشی و نتایج ناموفق (فقط-افزودنی) را یکپارچه می‌سازد. ۱۴ مهارت تخصصی دانشگاهی به عنوان تولیدکننده و مصرف‌کننده وضعیت پژوهش تاییدشده عمل می‌کنند و به صورت بومی از Claude Code، Cursor، Codex، Gemini CLI و Hermes Agent پشتیبانی می‌نمایند. دامنه اعتبارسنجی و محدودیت‌های سرویس‌های خارجی در [گزارش ممیزی](../../docs/kernel-architecture.md) ثبت شده است.

نویسنده: Junfu Shi (SJF, xngg1021)، Hermes Agent. محدوده مجوز فعلی: [Source Lineage License 1.0](../../LICENSE).

## شروع سریع

نسخه 2.2.0 را با استفاده از [uv](https://docs.astral.sh/uv/getting-started/installation/) اجرا کنید:

```bash
uvx academic-research-kernel@2.2.0 mcp
```

[انتشار نسخه 2.2.0](https://github.com/xngg1021/academic-research-kernel/releases/tag/v2.2.0) هش‌های بسته‌های توزیع و وضعیت انتشار را ثبت می‌کند. بسته wheel منتشرشده را می‌توان به صورت محلی نیز با دستور `uvx --from ./academic_research_kernel-2.2.0-py3-none-any.whl academic-research-kernel mcp` اجرا کرد. نسخه‌های Python 3.10 تا 3.14 پشتیبانی می‌شوند؛ گزینه `uvx --python 3.12` به طور صریح یک مفسر پشتیبانی‌شده را انتخاب می‌کند. هر ۱۲ ابزار قطعی، از جمله ابزارهای محاسبات علمی و تحلیل آماری، در نصب پایه گنجانده شده‌اند.

## بررسی نصب

```bash
uvx academic-research-kernel@2.2.0 doctor
uvx academic-research-kernel@2.2.0 --version
```

ابزار عیب‌یابی آفلاین، وابستگی‌ها، اسکیماها و هر ۱۲ تعریف ابزار را بررسی می‌کند. سرویس‌های خارجی اختیاری می‌توانند پیکربندی‌نشده باقی بمانند. برای دریافت خروجی قابل خواندن توسط ماشین از `doctor --json` استفاده کنید.

## نصب بسته نرم‌افزاری

```bash
uv tool install academic-research-kernel==2.2.0
academic-research-kernel doctor
academic-research-kernel mcp
```

همچنین می‌توانید بسته را با دستور `pipx install academic-research-kernel==2.2.0` یا `python -m pip install academic-research-kernel==2.2.0` در داخل یک محیط مجازی پشتیبانی‌شده نصب کنید. گزینه `[full]` کتابخانه‌های لازم برای مثال‌های علمی گسترده‌تر را اضافه می‌کند؛ گزینه `[qa]` ابزارهای اعتبارسنجی مخزن از جمله تجزیه‌گر PDF را می‌افزاید. گزینه `[research]` بسته‌های `pypdf==6.19.0` و `fonttools==4.65.0` را برای رمزگشایی یکنواخت فونت‌های PDF در محیط‌های نصب تمیز اضافه می‌کند که هر دو از Python 3.10 پشتیبانی می‌کنند. خواندن فایل‌های ساختاریافته HTML/XML و فایل‌های DOCX/XLSX با حجم محدود از کتابخانه استاندارد پایتون بهره می‌برد. بک‌اندهای GPU و سرویس‌های تجاری همچنان اختیاری هستند.

## Hermes

ابزار uv را طوری نصب کنید که در متغیر محیطی `PATH` فرآیند Hermes قرار داشته باشد، سپس افزونه قابل حمل را نصب و به صورت صریح فعال کنید:

```bash
hermes plugins install xngg1021/academic-research-kernel --no-enable
hermes plugins enable academic-skills
```

شناسه موجود `academic-skills` برای سازگاری با نسخه‌های پیشین حفظ شده و شامل ۱۴ مهارت از جمله `paper-research` است. فایل `mcp.json` افزونه، دستور `uv run --frozen --no-dev --no-editable` را با Python 3.12 و فایل قفل `uv.lock` مخزن فراخوانی می‌کند و محیط اجرای مستقل آن در مسیر `${PLUGIN_DATA}/runtime` قرار می‌گیرد. این افزونه در اولین استفاده، بدون قرض گرفتن بسته‌های پایتون Hermes یا سیستم‌عامل، وابستگی‌ها را راه‌اندازی می‌کند. اولین اجرا برای دریافت بسته‌ها یا مفسر ناموجود به اتصال شبکه نیاز دارد. روش قدیمی نصب صرفاً مهارت‌ها از طریق `tap` همچنان در بخش یکپارچه‌سازی و استفاده قابل حمل در ادامه پشتیبانی می‌شود.

## اجرا از کد منبع

```bash
git clone https://github.com/xngg1021/academic-research-kernel.git
cd academic-research-kernel
uv sync --frozen --no-dev --no-editable
```

برای اطلاع از طبقه‌بندی وابستگی‌ها، مراحل بازتولید، هویت نسخه، نقاط بررسی انتشار و دامنه اعتبارسنجی به [راهنمای توزیع و انتشار](../../docs/distribution-release.md) مراجعه کنید.

## استانداردهای علمی و خط پایه چندالگویی

سبک‌های استناددهی، ضوابط گزارش‌دهی و قراردادهای فراداده به مجله هدف، موسسه، نهاد تامین مالی، رشته علمی و حوزه قضایی بستگی دارند. این مخزن استانداردهای **ISO 690:2021** (ارجاعات کتاب‌شناختی)، **ISO 5127:2017** (واژگان اطلاعات و مستندسازی) و **W3C PROV** (مدل داده منشأ) را به عنوان خطوط پایه بین‌المللی در کنار الگوهای منطقه‌ای (مانند GB/T 7714-2025 در سرزمین اصلی چین، UNE-ISO 690:2024 در اسپانیا و DIN ISO 690:2021 در آلمان) و استانداردهای رشته‌ای (APA 7th، IEEE، ACM، Vancouver، Chicago، PRISMA 2020 و ICMJE) مستقر می‌سازد. الزامات محل انتشار هدف همواره بر الگوهای پیش‌فرض مقدم هستند. به [معماری استانداردهای علمی](../../docs/standards/README.md) و [راهنمای اصطلاحات طبیعی](../../docs/terminology/README.md) مراجعه کنید.

اصلاح نهایی اعتبارسنجی هسته، سازگاری شناسه‌ها و DOI، پرچم‌های حکم کمی مانعةالجمع، و قرارداد مشترک میان هسته و رسید برای موارد نیازمند بررسی را تایید می‌کند. تمامیت حافظه نهان (cache) مستقل از فهرست تغییرات رسید، از پاکت‌های منبع نگهداری‌شده و پیوندهای نرمال‌شده بازسازی می‌شود؛ بنابراین حذف هم‌زمان یک رکورد و اعلان کش آن نمی‌تواند یک بازپخش پذیرفته‌شده ایجاد کند. جزئیات بیشتر را در [گزارش بستن چهار مانع](../../docs/kernel-architecture.md) ببینید.

## یکپارچه‌سازی و استفاده قابل حمل

### 1. Universal Agent Plugins v1 & Model Context Protocol (MCP)
این مخزن از مشخصات مستقل از فروشنده **Agent Plugins v1** (`../../plugin.json`) پیروی می‌کند و ابزارهای اصلی راستی‌آزمایی دانشگاهی و محاسبه مجدد آماری را از طریق یک **سرور MCP** مبتنی بر stdio (`../../mcp.json` / `../../scripts/mcp_server.py`) در دسترس قرار می‌دهد. این ساختار با Claude Code، Cursor، Gemini CLI و هر چارچوب عامل مدرن سازگار است. (توجه: با اینکه شناسه مخزن `academic-research-kernel` است، نام مانیفست افزونه یعنی `academic-skills` و نام‌های مستعار پیکربندی MCP برای حفظ سازگاری با نسخه‌های پیشین ثابت مانده‌اند.)

```bash
# Add as stdio MCP server in your agent harness
uvx academic-research-kernel mcp
```

### 2. نصب بومی در Hermes
از محیط نصب‌شده Hermes دستورات زیر را اجرا کنید:

```bash
hermes skills tap add xngg1021/academic-research-kernel
hermes skills search academic-source-verification
hermes skills install xngg1021/academic-research-kernel/skills/academic-source-verification
```

سایر مهارت‌ها را با جایگزینی نام دایرکتوری در شناسه کامل نصب کنید. دستور `tap` معمولی شاخه پیش‌فرض را می‌خواند، بنابراین یک نصب تازه مجموعه مهارت‌های بالا را فراهم می‌کند. برای بررسی یک شاخه کاری پیش از ادغام، آن شاخه را به صورت محلی دریافت (checkout) کرده و دستورالعمل نصب از پوشه محلی مربوط به نسخه Hermes خود را دنبال کنید. فرض نکنید که دستور `tap` شاخه یک درخواست ادغام را انتخاب می‌کند.

مهارت‌های همراه مرتبط در کامیت بالادستی `245e48008fa814b3251f50755eb656bd9fb86cb1` بررسی شده‌اند: arxiv، grounded-citations، docx، pdf و manim-video. بسته‌های huggingface-hub و llama-cpp در فهرست اختیاری قرار دارند و ممکن است نیازمند نصب جداگانه باشند. موارد ocr-and-documents و pc-hardware-benchmark در آن نسخه یافت نشدند و جزو وابستگی‌ها نیستند. ابزارهای نشست و بک‌اندهای اسناد یا مرورگر به پیکربندی محلی سیستم بستگی دارند.

## دسترسی به منابع داده

- پرس‌وجوهای پایه OpenAlex را می‌توان به صورت ناشناس با بودجه روزانه محدود اجرا کرد. مستندات بررسی‌شده در تاریخ 2026-09-06 سقف روزانه ۰٫۱۰ دلار برای حالت ناشناس و ۱ دلار برای کلید API رایگان، به همراه سقف ۱۰۰ درخواست در ثانیه را مشخص می‌کنند. هزینه بسته به نوع پرس‌وجو متفاوت است و دسترسی نامحدود محسوب نمی‌شود. کلید اختیاری را در متغیر `OPENALEX_API_KEY` ذخیره کنید و از `per_page` (حداکثر ۱۰۰) و صفحه‌بندی مبتنی بر مکان‌نما (cursor pagination) بهره ببرید.
- سامانه Crossref دسترسی عمومی به فراداده‌ها را با محدودیت نرخ درخواست فراهم می‌کند. روابط به‌روزرسانی و سیگنال‌های Retraction Watch نیازمند بررسی DOI و جهت ارتباط هستند؛ نبود رکورد ثابت نمی‌کند که مقاله تحت تاثیر قرار نگرفته است.
- سامانه Unpaywall نیازمند ثبت یک ایمیل تماس واقعی در متغیر `UNPAYWALL_EMAIL` است. بازنگشتن مسیر فایل ثابت نمی‌کند که هیچ نسخه دسترسی آزادی (OA) وجود ندارد.
- پایگاه‌های arXiv، Europe PMC، PubMed E-utilities و DOAJ منابع تکمیلی با سیاست‌های اختصاصی خود هستند و آزمون‌های پیش‌فرض همه آن‌ها را فراخوانی نمی‌کنند. پایگاه Semantic Scholar دارای محدودیت مشترک ناشناس و سهمیه مجزای کلید اختصاصی است؛ دسترسی به API تضمین‌کننده در دسترس بودن متن زمینه استناد نیست.
- سرویس‌های Scite، Dimensions، Scopus، Web of Science و محصولات تشخیص متن هوش مصنوعی، سرویس‌های خارجی اختیاری هستند. پیش از استفاده، مجوزهای حساب، دسترسی‌های API و سهمیه‌های فعلی را بررسی کنید؛ هیچ سطح رایگان همگانی یا قیمت ثابتی تضمین نمی‌شود.

به مستندات [احراز هویت OpenAlex](https://help.openalex.org/api/authentication/)، [بودجه و هزینه پرس‌وجوها](https://help.openalex.org/api/llm-quick-reference/) و [فیلترهای به‌روزرسانی Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/) مراجعه کنید.

## ورود قطعی داده‌ها و هسته عمومی

لایه ورود و تجزیه مصنوعات پژوهشی، ساختارهای `ResearchArtifactEnvelope v1` و `ArtifactIngestionReceipt v1`، تعداد ۱۵ مبدل (شامل ۱۴ مهارت به همراه مسیر پشتیبان متن ساختارنیافته opaque fallback) و ۱۲ ابزار بدون وضعیت stdio MCP را فراهم می‌سازد. رسیدهای پذیرش تاییدشده، هر تغییر معنایی ذخیره‌شده را بر اساس نوع، شناسه و هش استاندارد SHA-256 مقید می‌کنند: موجودیت‌ها، رکوردهای CEG، رکوردهای دفتر تصمیمات، موارد نیازمند بررسی، رسیدهای فیزیکی و ثبت مصنوعات پژوهشی. بازپخش حافظه نهان این تعهدات را مستقل از هش‌های تصویر انتقال بررسی می‌کند. دفترهای خالی معتبر هستند و دسته‌های تراکنش اتمی ناموفق هیچ وضعیت ناقصی بر جای نمی‌گذارند.

مجوز دسترسی به محتوای تبارنامه به صورت صريح و خارج از باند (out of band) اعطا می‌شود. فراخواننده‌های مورد اعتماد Python هنگام بازپخش رسیدها یا تصاویر سریال‌شده، شیء `LineageVerificationContext` را ارسال می‌کنند؛ فراخواننده‌های MCP تنها مجاز به ارسال بایت‌های محتوا با حجم محدود هستند و هرگز نمی‌توانند ریشه سیستم فایل میزبان را معرفی کنند. بودجه پیش‌فرض محتوا ۱۰ مبي‌بایت (10 MiB) است و یک میزبان مورد اعتماد می‌تواند تحت سیاست یکسان میان تولیدکننده و راستی‌آزما، مصنوعات بزرگ‌تر را به طور صریح مجاز شمارد. بدون مجوز دسترسی به محتوا، یک ادعای دارای وضعیت `fully_verified` قابل بازتولید مستقل نیست و نتیجه راستی‌آزمایی نامعتبر ساختاریافته برمی‌گرداند. متون ساختارنیافته به صورت غیرشفاف باقی می‌مانند، نظرات مخالف قابل مشاهده حفظ می‌شوند و پژوهشگران کنترل کامل ثبت نهایی، توقف مسیرها، بازگشایی، مسیریابی و داوری درباره درستی علمی را در اختیار دارند.

برای مشاهده قراردادها و قواعد سازگاری به [مستند معماری هسته](../../docs/kernel-architecture.md) مراجعه کنید. نقاط بررسی توزیع و انتشار در [راهنمای انتشار](../../docs/distribution-release.md) ثبت شده‌اند. فایل‌های README انگلیسی و چینی ساده‌شده به‌روز هستند و وضعیت سایر ترجمه‌ها به طور شفاف در [مانیفست همگام‌سازی](../../docs/i18n/manifest.json) درج شده است. هویت نامزد نهایی، نتایج CI بر روی HEAD دقیق، داوری‌های تجمعی و شواهد ادغام در [دفتر جمع‌بندی](https://github.com/xngg1021/academic-research-kernel/pull/12#issuecomment-5754741342) ثبت شده‌اند.

## اعتبارسنجی (Validation)

از یک محیط اختصاصی Python استفاده کنید. کتابخانه‌های زمان اجرا وابسته به وظیفه هستند و نصب بودن آن‌ها در Hermes تضمین نمی‌شود. وابستگی‌های QA گسترده‌تر هستند تا تمام مثال‌های نشانه‌گذاری‌شده قابل اجرا باشند:

```bash
python -m pip install -r requirements-qa.txt
python -m pip install 'torch>=2.5,<3' --index-url https://download.pytorch.org/whl/cpu
python scripts/qa.py
python -m pytest -q -rs tests
python scripts/i18n_sync.py --check
python scripts/verify_external_apis.py --output external-status.json --summary external-summary.md
git diff --check
```

سامانه QA فراداده‌ها، مراجع، الگوهای مسیرهای شخصی یا کلیدهای محرمانه شناخته‌شده، نحو Python و بلوک‌های کد قابل اجرای نشانه‌گذاری‌شده را اعتبارسنجی می‌کند. هر مثال آزمون سریع (smoke test) بدون تغییر در یک زیرفرآیند تازه اجرا می‌شود. مثال‌های ترسیم نمودار متغیر `PLOT_DIR` (پیش‌فرض `~/plots` با بسط صریح مسیر) را می‌پذیرند و آزمون‌ها از یک دایرکتوری موقت استفاده می‌کنند. بلوک‌های کد Python طبقه‌بندی‌نشده رد می‌شوند؛ بلوک‌های `fragment:` از نظر نحوی بررسی می‌شوند اما نیازمند ورودی‌های نام‌گذاری‌شده هستند و به صورت مستقل اجرا نمی‌گردند. بلوک‌های `external-test:` تنها از طریق دستور دستی بررسی خارجی اجرا می‌شوند. این دستور در صورت موفقیت بررسی‌های پیکربندی‌شده کد ۰، در صورت خطای کد/اسکیما/هویت کد ۱، و در صورت عدم دسترسی به شبکه/احراز هویت/سهمیه کد ۲ را برمی‌گرداند؛ سرویس‌های اختیاری پیکربندی‌نشده در وضعیت SKIP باقی می‌مانند.

آزمون‌های نگارش مهارت Hermes با نسخه ثابت، بدون تغییر قواعد هر مهارت بازاستفاده می‌شوند. بررسی‌های جمعیتی کل توزیع بالادستی بر این مخزن اعمال نمی‌شود؛ چارچوب آزمون ما چهارده مهارت را بررسی کرده و مراجع را در برابر فهرست بسته‌های همراه و اختیاری نسخه‌بندی‌شده تحلیل می‌کند. این فرآیند یک آزمون نصب کامل Hermes نیست. سامانه CI تنها برای نصب وابستگی‌ها از شبکه استفاده می‌کند و آزمون‌های معمولی APIهای علمی را فراخوانی نمی‌کنند.

سامانه CI مجموعه کامل QA را روی Linux x86_64 (با Python 3.10–3.14)، Linux ARM64 (ubuntu-24.04-arm)، نسخه پیش‌نمایش Ubuntu 26.04 canary (ubuntu-26.04 و ubuntu-26.04-arm)، Windows x86_64، Windows ARM64 (windows-11-arm)، macOS ARM64 (macos-latest) و macOS Intel (macos-15-intel) به همراه اعتبارسنجی زنده canary در برابر مخزن بالادستی اجرا می‌کند. نامزد انتشار پایه ۱۱۶۵ آزمون محلی را با موفقیت پشت سر گذاشت. نتایج اصلاحات فعلی و مرزهای پوشش در [گزارش اصلاح درستی](../../docs/maintenance/correctness-repair-20261008.md) ثبت شده و شواهد راه‌دور شناسه HEAD آزمایش‌شده را به طور جداگانه مشخص می‌کنند. یک جریان کاری مجزا برای یکپارچه‌سازی `tap` هنگام ارسال کد به شاخه `main` اجرا می‌شود که نسخه Hermes ثبت‌شده در `tests/upstream/provenance.json` را نصب کرده و دستورات `tap add`، `search`، `install` و `list` را روی این مخزن آزمایش می‌کند. نسخه‌های دقیق، موارد بررسی و محدودیت‌ها در [گزارش ممیزی](../../docs/kernel-architecture.md) آمده است.

مسیر [tools/longtail/](../../tools/longtail/README.md) نگهدارنده مولد قطعی فاکتورهای دنباله بلند (long-tail) است: ۴۰۹۶ نامزد تولیدشده با بذر SHA256، ۳۰ سناریوی برگزیده و یک گزارش پوشش راستی‌آزمایی محاسبه‌شده توسط ماشین. مدل نسخه ۳ خانواده‌های قابلیت (E01)، ۱۴ مهارت واقعی موجود در مخزن (E02) و اهداف وظیفه (E03) را به صورت جداگانه شمارش می‌کند. هر سناریو دارای یک مهارت اصلی، یک هدف وظیفه پشتیبانی‌شده و قابلیت‌های سازگار است؛ هر مهارت باید حداقل دو بار تحت دو هدف متفاوت، از جمله هدف اصلی اعلام‌شده خود، ظاهر شود. انحراف در دایرکتوری مهارت‌ها باعث شکست اعتبارسنجی می‌شود. بسط معنایی (زنجیره‌های وظیفه، معیارهای سنجش و تزریق رویدادهای اجرایی) همچنان یک مرحله جداگانه است و پوشش فاکتورها به معنای اثبات پوشش اجرای جریان کاری نیست.

مسیر `scripts/scfabric/` لایه اجرایی ابزارهای محاسبات علمی و تحلیل آماری است: کاوشگر سخت‌افزار، فهرست بک‌اندها با دروازه‌های نوع داده (`dtype`)، پنج نمایه بار کاری، بنچمارک زوجی همراه با پذیرش برابری عددی و `ComputeReceipt`. اندازه‌گیری‌های دور اول روی این دستگاه در [docs/scientific-compute-fabric.md](../../docs/scientific-compute-fabric.md) ثبت شده‌اند؛ قاعده کلی استفاده پیش‌فرض از CPU و فعال‌سازی شتاب‌دهنده صرفاً با وجود رسید معتبر است.

## پژوهش روی مقاله با استفاده از Agent محلی

بسته `academic-research-kernel[research]==2.2.0` را نصب کرده و جریان کاری بسته‌بندی‌شده را استخراج کنید:

```sh
academic-research-kernel research skill --output ./agent-skills/paper-research
```

اجازه دهید Work یا یک Agent محلی سازگار، فایل `SKILL.md` استخراج‌شده را بخواند و سپس از او بخواهید:
“研究这篇论文及其补充材料，整理方法，核对能重算的关键数字，给我一份带出处的中文报告。”
تنها شناسه DOI، پیوند عمومی یا بسته فایل‌های محلی را در اختیارش بگذارید. برای دو مقاله، از او بخواهید داده‌ها، روش‌ها، شرایط ارزیابی و نتایج را مقایسه کند و توضیح دهد کدام بخش‌ها مستقیماً قابل مقایسه‌اند. عامل هوشمند در همان وظیفه مراحل خوانش متن اصلی، اعتبارسنجی فیلدهای پیشنهادی، محاسبه مجدد، ورود به هسته، تولید گزارش و ارزیابی و راستی‌آزمایی مستقل منابع را به صورت پیوسته انجام می‌دهد. سطح موجود MCP همچنان ۱۲ ابزار خود را حفظ می‌کند و هماهنگ‌سازی جدید در رابط خط فرمان (CLI) و مهارت قابل حمل قرار دارد.

مراحل واقعی اجرای برنامه عبارت‌اند از:

```sh
academic-research-kernel research prepare INPUT --project PROJECT
academic-research-kernel research finish --project PROJECT --candidate CANDIDATE.json
academic-research-kernel research compare LEFT_PROJECT RIGHT_PROJECT --analysis COMPARISON.json --output OUTPUT
```

دستور `prepare` مواد پژوهشی را دریافت و به مانیفست، هش‌های منبع و قطعات متنی مکان‌یابی‌شده تجزیه می‌کند. دستور `finish` داده‌های استخراج‌شده توسط Agent را اعتبارسنجی کرده و ادعاهای واجد شرایط آزمون t/p، اندازه اثر دو گروه و شمارش/درصد را با ابزارهای آماری موجود دوباره محاسبه می‌کند و در نهایت وضعیت هسته و گزارش‌های چینی Markdown/HTML را ذخیره می‌نماید. دستور `compare` ارزیابی صريح Agent از شرایط قابل مقایسه را بررسی می‌کند. این دستورات یک مدل مقیم دائمی را در خود جای نداده‌اند: خوانش معنایی توسط Agent فعلی و با پیروی از [paper-research](../../skills/paper-research/SKILL.md) انجام می‌شود. فایل‌های اصلی ذخیره‌شده و تصاویر استخراج، از بازپخش قطعی آفلاین پشتیبانی می‌کنند. دریافت از شبکه و خوانش معنایی جدید همچنان به عنوان عملیات‌های مجزا شناخته می‌شوند.

## اصلاحات درستی نسخه 2.0.1 و راستی‌آزمایی توزیع

انتشار محصول 2.0.1 شامل اصلاحات درستی برای محاسبه مجدد آماری، ردیابی سلب اعتبار مقالات و مدیریت نشست MCP است. ابزار عمومی `academic_recompute_statistics` مقادیر p آزمون t و شاخص‌های Cohen's d و Hedges' g دو گروه را ارائه می‌دهد. فواصل اطمینان (CI) و نسبت شانس/خطر (OR/RR) به صورت توابع سطح پایین‌تر Python باقی می‌مانند. زمانی که دقت اعشار گزارش اهمیت دارد، پارامتر `p_value_literal` (برای نمونه `"1.0e-5"`) یا `p_value_decimals` را ارسال کنید. مقادیر رشته‌ای صفرهای پایانی را حفظ می‌کنند؛ ورودی‌های عددی تنها نمایش عددی خود را نگه می‌دارند. منابع دقت متناقض به طور صریح با خطا متوقف می‌شوند. مقایسه‌های گرد کردن به بالا (round-half-up) مرز پایینی گرد کردن را شامل شده و مرز بالایی را خارج می‌کنند. یک مغایرت آماری عادی، نتیجه علمی موفق محسوب می‌شود؛ اما محاسبات نامعتبر یا ناتمام پرچم `isError` را فعال می‌کنند.

بررسی‌های سلب اعتبار مقاله (retraction)، مشاهده فعلی (`True`/`False`/`unknown`) را جدا از آخرین مقدار شناخته‌شده (`last-known`) ثبت می‌کنند. یک رزرو کوتاه پیش از پرس‌وجو، مشاهدات مربوط به یک DOI واحد را مرتب کرده و به‌روزرسانی‌های سایر DOIها را حفظ می‌نماید. مشاهدات فعلی و تاییدیه‌های تاریخی دارای نسخه‌بندی جداگانه هستند: یک تاییدیه معتبر که دیرتر دریافت شود می‌تواند تاریخچه نگهداری‌شده را ارتقا دهد، در حالی که وضعیت `unknown` جدیدتر برای بررسی فعلی به طور صریح تاییدنشده باقی می‌ماند. داده‌های ثابت HTTP در زنجیره‌های آزمون رگرسیون به عنوان داده‌های آزمایشی برچسب‌گذاری شده‌اند.

سرور MCP به دستور `ping` پاسخ می‌دهد، در برابر اعلان‌های معتبر (از جمله `notifications/cancelled`) سکوت اختیار می‌کند و پس از دریافت ورودی نامعتبر، نشست stdio را فعال نگه می‌دارد. پیاده‌سازی همگام، قابلیت لغو پیش‌دستانه (preemptive cancellation) را اعلام نمی‌کند. مدیریت پیام‌ها از [قرارداد پیام MCP](https://modelcontextprotocol.io/specification/2024-11-05/basic/messages) و [مشخصات ping](https://modelcontextprotocol.io/specification/2024-11-05/basic/utilities/ping) پیروی می‌کند.

توزیع‌های این نسخه را در یک محیط ایزوله بسازید و راستی‌آزمایی کنید:

```bash
python -m build
python -m twine check --strict dist/*
python scripts/package_acceptance.py --dist dist --uvx --source-checks --report package-acceptance.json
```

گزینه `--source-checks` بسته نامزد `sdist` را بدون تغییر در خارج از محیط مخزن باز می‌کند، متغیرهای `ARK_REPO` و `ARK_SDIST` را روی آن نامزد تنظیم می‌نماید و آزمون‌ها، QA ایستا، بلوک‌های کد قابل اجرا و بررسی همگام‌سازی زبان‌ها (i18n) را اجرا می‌کند. نصب‌های `wheel` و `sdist` هر یک از محیطی کاملاً تازه استفاده می‌کنند و `uvx` از بسته `wheel` محلی با حافظه نهان مستقل بهره می‌برد. گزارش خروجی، هش مصنوعات و مسیرهای واقعی بارگذاری ماژول‌ها را ثبت می‌کند. بررسی‌های سبک و زمان‌بندی‌شده Hermes، شناسه SHA آزمایش‌شده را برای نسخه‌های ثابت (pinned) و جدیدترین (latest) به طور مستقل گزارش می‌دهند. فایل JSON قرارداد خارجی و خلاصه وضعیت اجرا از وضعیت‌های `healthy`، `degraded` و `failed` استفاده می‌کنند و کاوش‌های ردشده به صورت صریح مشخص می‌مانند.
