ایجنٹ پر مبنی تحقیقی ورک فلو کے لیے پلیٹ فارم سے آزاد اور قطعی (deterministic) علمی تحقیقی کیفیت کا انتظامی نظام۔ یہ نظام تحقیقی مواد کی شمولیت اور تجزیہ کرنے والے قطعی پل اور عالمگیر Model Context Protocol (MCP) سرور کے ذریعے تحقیقی اشیاء کی شناخت، تجرباتی ثبوت / تصدیقی ریکارڈ، سہ طرفہ دعووں اور شواہد کے روابط (CEG) اور صرف اندراج کے قابل تحقیقی فیصلوں اور منفی نتائج کا لاگ یکجا کرتا ہے۔ 14 مخصوص علمی مہارتیں تصدیق شدہ تحقیقی کیفیت کے پیدا کنندہ اور صارف دونوں کے طور پر کام کرتی ہیں، اور Claude Code، Cursor، Codex، Gemini CLI اور Hermes Agent کے لیے براہ راست مطابقت فراہم کرتی ہیں۔ تصدیق کا دائرہ کار اور بیرونی خدمات کی حدود [آڈٹ دستاویز](../../docs/project-lineage-audit-20260920.md) میں درج ہیں۔

مصنف: Junfu Shi (SJF, xngg1021)، Hermes Agent۔ موجودہ لائسنس پیشکش: [Source Lineage License 1.0](../../LICENSE)۔

## فوری آغاز

[uv](https://docs.astral.sh/uv/getting-started/installation/) کے ساتھ ورژن 2.2.0 چلائیں:

```bash
uvx academic-research-kernel@2.2.0 mcp
```

[2.2.0 ریلیز](https://github.com/xngg1021/academic-research-kernel/releases/tag/v2.2.0) ڈسٹری بیوشن ہیشز اور اشاعت کی حیثیت کو ریکارڈ کرتی ہے۔ ریلیز وہیل کو مقامی طور پر `uvx --from ./academic_research_kernel-2.2.0-py3-none-any.whl academic-research-kernel mcp` کے ذریعے بھی چلایا جا سکتا ہے۔ Python 3.10–3.14 معاونت یافتہ ہے؛ `uvx --python 3.12` واضح طور پر ایک معاون انٹرپریٹر منتخب کرتا ہے۔ سائنسی حساب کتاب اور شماریاتی آلات سمیت تمام 12 قطعی ٹولز بنیادی انسٹالیشن میں شامل ہیں۔

## تنصیب کی تصدیق

```bash
uvx academic-research-kernel@2.2.0 doctor
uvx academic-research-kernel@2.2.0 --version
```

آف لائن تشخیصی عمل انحصار (dependencies)، اسکیماز اور تمام 12 ٹول تعریفوں کی جانچ کرتا ہے۔ اختیاری بیرونی خدمات کو بغیر کنفیگر کیے چھوڑا جا سکتا ہے۔ مشین کے پڑھنے کے قابل آؤٹ پٹ کے لیے `doctor --json` استعمال کریں۔

## پیکیج کی تنصیب

```bash
uv tool install academic-research-kernel==2.2.0
academic-research-kernel doctor
academic-research-kernel mcp
```

متبادل کے طور پر، کسی معاون ورچوئل ماحول کے اندر `pipx install academic-research-kernel==2.2.0` یا `python -m pip install academic-research-kernel==2.2.0` کے ذریعے انسٹال کریں۔ `[full]` توسیعی سائنسی مثالوں کے لیے لائبریریاں شامل کرتا ہے؛ `[qa]` پی ڈی ایف پارسر سمیت ریپوزٹری کی تصدیق کے ٹولز شامل کرتا ہے۔ `[research]` صاف انسٹالیشنز میں یکساں پی ڈی ایف فونٹ ڈی کوڈنگ کے لیے `pypdf==6.19.0` اور `fonttools==4.65.0` شامل کرتا ہے؛ دونوں Python 3.10 کی معاونت کرتے ہیں۔ منظم HTML/XML اور محدود حجم کی DOCX/XLSX فائلوں کو پڑھنے کے لیے معیاری لائبریری استعمال ہوتی ہے۔ GPU بیک اینڈز اور بامعاوضہ خدمات اختیاری رہتی ہیں۔

## Hermes

uv کو اس طرح انسٹال کریں کہ وہ Hermes کے پراسیس PATH میں موجود ہو، پھر پورٹیبل پلگ ان کو انسٹال اور واضح طور پر فعال کریں:

```bash
hermes plugins install xngg1021/academic-research-kernel --no-enable
hermes plugins enable academic-skills
```

موجودہ `academic-skills` شناخت کو برقرار رکھا گیا ہے، جس میں اب `paper-research` سمیت 14 مہارتیں شامل ہیں۔ پلگ ان کی `mcp.json` فائل Python 3.12 اور چیک آؤٹ کے `uv.lock` کے ساتھ `uv run --frozen --no-dev --no-editable` کو کال کرتی ہے؛ اس کا اپنا رن ٹائم ماحول `${PLUGIN_DATA}/runtime` کے تحت رہتا ہے۔ یہ Hermes یا سسٹم کے Python پیکیجز ادھار لیے بغیر، پہلے استعمال پر خودکار طور پر ضروری پیکیجز تیار کر لیتا ہے۔ غائب پیکیجز یا انٹرپریٹر حاصل کرنے کے لیے پہلے استعمال پر نیٹ ورک تک رسائی درکار ہوتی ہے۔ صرف مہارتیں انسٹال کرنے والا پرانا ٹیپ طریقہ نیچے انضمام اور پورٹیبل استعمال کے حصے میں اب بھی معاونت یافتہ ہے۔

## انضمام اور پورٹیبل استعمال

### 1. Universal Agent Plugins v1 & Model Context Protocol (MCP)
یہ ریپوزٹری وینڈر سے غیر جانبدار **Agent Plugins v1** وضاحت (`../../plugin.json`) کی پابندی کرتی ہے اور stdio **MCP سرور** (`../../mcp.json` / `../../scripts/mcp_server.py`) کے ذریعے بنیادی علمی تصدیق اور شماریاتی دوبارہ حساب کے ٹولز فراہم کرتی ہے۔ یہ Claude Code، Cursor، Gemini CLI اور کسی بھی جدید ایجنٹ فریم ورک کے ساتھ ہم آہنگ ہے۔ (نوٹ: اگرچہ ریپوزٹری کی شناخت `academic-research-kernel` ہے، تاہم سابقہ ورژنز سے مطابقت کے لیے پلگ ان مینی فیسٹ کا نام `academic-skills` اور MCP کنفیگریشن کے متبادل نام مستحکم رکھے گئے ہیں۔)

```bash
# Add as stdio MCP server in your agent harness
uvx academic-research-kernel mcp
```

## ڈیٹا ذرائع تک رسائی

- OpenAlex کے بنیادی سوالات چھوٹے یومیہ بجٹ کے ساتھ گمنام طور پر چلائے جا سکتے ہیں۔ 2026-09-06 کی دستاویزات کے مطابق گمنام طور پر $0.10/دن اور مفت API کلید کے ساتھ $1/دن کے علاوہ 100 درخواستیں فی سیکنڈ کی حد مقرر ہے۔ سوال کی نوعیت کے لحاظ سے لاگت مختلف ہوتی ہے؛ یہ لامحدود رسائی نہیں ہے۔ اختیاری کلید کو `OPENALEX_API_KEY` میں محفوظ کریں۔ `per_page` (زیادہ سے زیادہ 100) اور کرسر پیجینیشن استعمال کریں۔
- Crossref رفتار کے کنٹرول کے ساتھ عوامی میٹا ڈیٹا تک رسائی فراہم کرتا ہے۔ اپ ڈیٹ کے تعلقات اور Retraction Watch کے اشاروں کے لیے DOI اور سمت کی جانچ ضروری ہے؛ ریکارڈ کی عدم موجودگی یہ ثابت نہیں کرتی کہ مقالہ متاثر نہیں ہوا۔
- Unpaywall کے لیے `UNPAYWALL_EMAIL` میں ایک حقیقی رابطہ ای میل درکار ہے۔ کسی مقام کا نہ ملنا یہ ثابت نہیں کرتا کہ اوپن ایکسیس (OA) کاپی موجود نہیں ہے۔
- arXiv، Europe PMC، PubMed E-utilities اور DOAJ اپنی پالیسیوں کے حامل تکمیلی ذرائع ہیں۔ ڈیفالٹ ٹیسٹ ان سب کو نہیں چلاتے۔ Semantic Scholar میں مشترکہ گمنام حدود اور الگ سے تفویض کردہ کلید کی حدود ہیں؛ API تک رسائی حوالہ جات کے متن کی دستیابی کی ضمانت نہیں دیتی۔
- Scite، Dimensions، Scopus، Web of Science اور AI تشخیصی مصنوعات اختیاری بیرونی خدمات ہیں۔ استعمال سے پہلے موجودہ اکاؤنٹ/API کے حقوق اور کوٹہ چیک کریں؛ کسی عالمگیر مفت درجے یا مقررہ قیمت کا وعدہ نہیں کیا جاتا۔

مزید تفصیل کے لیے [OpenAlex توثیق](https://help.openalex.org/api/authentication/)، [بجٹ اور سوالات کی لاگت](https://help.openalex.org/api/llm-quick-reference/)، اور [Crossref اپ ڈیٹ فلٹرز](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/) دیکھیں۔

## قطعی شمولیت اور عوامی کرنل

تحقیقی مواد کی شمولیت اور تجزیہ کرنے والی تہہ `ResearchArtifactEnvelope v1`، `ArtifactIngestionReceipt v1`، 15 اڈاپٹرز (14 مہارتیں بمعہ غیر منظم متن کا متبادل opaque fallback)، اور 12 اسٹیٹ لیس stdio MCP ٹولز فراہم کرتی ہے۔ منظور شدہ شمولیت کی رسیدیں ہر محفوظ کردہ معنوی تبدیلی کو قسم، شناخت اور معیاری SHA-256 کے ذریعے پابند کرتی ہیں: اشیاء، CEG ریکارڈز، فیصلوں کے لاگ ریکارڈز، جائزے کے متقاضی امور، طبعی رسیدیں اور تحقیقی فن پاروں کی رجسٹریشن۔ کیشے ری پلے ٹرانسپورٹ اسنیپ شاٹ ہیشز سے آزادانہ طور پر ان وعدوں کی جانچ کرتا ہے۔ خالی لاگز درست ہیں؛ ناکام ایٹمی بیچز کوئی ادھوری حالت پیچھے نہیں چھوڑتے۔

شجرے کے مواد کا اختیار واضح اور آؤٹ آف بینڈ ہے۔ قابل اعتماد Python کالرز سیریلائزڈ رسیدوں یا اسنیپ شاٹس کو ری پلے کرتے وقت `LineageVerificationContext` پاس کرتے ہیں؛ MCP کالرز صرف محدود حجم کے مواد کے بائٹس فراہم کر سکتے ہیں، کبھی بھی ہوسٹ فائل سسٹم کا روٹ نہیں۔ مواد کا ڈیفالٹ بجٹ 10 MiB ہے؛ ایک قابل اعتماد ہوسٹ یکساں پیدا کنندہ اور تصدیق کنندہ پالیسی کے تحت بڑے فن پاروں کی واضح طور پر اجازت دے سکتا ہے۔ مواد کے اختیار کے بغیر، `fully_verified` دعوے کو آزادانہ طور پر دوبارہ پیدا نہیں کیا جا سکتا اور وہ ایک منظم غیر درست تصدیقی نتیجہ واپس کرتا ہے۔ غیر منظم نثر مبہم رہتی ہے، اختلافی رائے نمایاں رہتی ہے، اور محققین کمٹ کرنے، راستہ ترک کرنے، دوبارہ کھولنے، روٹنگ اور سچائی کے فیصلوں پر مکمل اختیار برقرار رکھتے ہیں۔

معاہدوں اور مطابقت کے لیے [کرنل کا تعمیراتی دستاویز](../../docs/kernel-architecture.md) دیکھیں۔ ڈسٹری بیوشن اور اشاعت کے چیک پوائنٹس [ریلیز گائیڈ](../../docs/distribution-release.md) میں درج ہیں۔ انگریزی اور آسان چینی README تازہ ترین ہیں؛ دیگر تراجم کی حالت [مینی فیسٹ](../../docs/i18n/manifest.json) میں واضح طور پر موجود ہے۔ حتمی امیدوار کی شناخت، درست HEAD CI، مجموعی جائزہ اور انضمام کے شواہد [اختتامی کھاتے](https://github.com/xngg1021/academic-research-kernel/pull/12#issuecomment-5754741342) میں محفوظ ہیں۔

## توثیق اور جانچ (Validation)

ایک مخصوص Python ماحول استعمال کریں۔ رن ٹائم لائبریریاں کام کے لحاظ سے مخصوص ہیں اور Hermes میں پہلے سے انسٹال ہونے کی ضمانت نہیں ہے۔ QA کے انحصار وسیع تر ہیں تاکہ تمام نشان زدہ مثالیں چل سکیں:

```bash
python -m pip install -r requirements-qa.txt
python -m pip install 'torch>=2.5,<3' --index-url https://download.pytorch.org/whl/cpu
python scripts/qa.py
python -m pytest -q -rs tests
python scripts/i18n_sync.py --check
python scripts/verify_external_apis.py --output external-status.json --summary external-summary.md
git diff --check
```

QA میٹا ڈیٹا، حوالہ جات، ذاتی راستوں یا معلوم خفیہ کلیدوں کے نمونوں، Python سنٹیکس اور نشان زدہ قابل عمل کوڈ بلاکس کی توثیق کرتا ہے۔ ہر اسموک مثال ایک نئے ذیلی پراسیس میں بغیر کسی تبدیلی کے چلتی ہے۔ گراف بنانے کی مثالیں `PLOT_DIR` (ڈیفالٹ `~/plots`، واضح طور پر توسیع شدہ) قبول کرتی ہیں؛ ٹیسٹ ایک عارضی ڈائریکٹری استعمال کرتے ہیں۔ غیر درجہ بند Python کوڈ بلاکس مسترد کر دیے جاتے ہیں؛ `fragment:` بلاکس کی سنٹیکس جانچ ہوتی ہے لیکن انہیں نامزد ان پٹ درکار ہوتے ہیں اور وہ اکیلے نہیں چلائے جاتے۔ `external-test:` بلاکس صرف دستی بیرونی کمانڈ کے ذریعے چلتے ہیں۔ کنفیگر کیے گئے چیکس پاس ہونے پر یہ 0، کوڈ/اسکیما/شناخت کی ناکامی پر 1، اور ٹرانسپورٹ/توثیق/کوٹہ کی عدم دستیابی پر 2 واپس کرتا ہے؛ غیر کنفیگر شدہ اختیاری خدمات SKIP رہتی ہیں۔

پن کیے گئے Hermes آتھرنگ ٹیسٹوں کو ان کے فی مہارت اصول بدلے بغیر دوبارہ استعمال کیا جاتا ہے۔ اپ اسٹریم کی مکمل ڈسٹری بیوشن آبادی کی جانچ اس ٹیپ پر لاگو نہیں ہوتی؛ ہمارا ٹیسٹ ہارنس چودہ مہارتوں کی جانچ کرتا ہے اور پن کیے گئے بنڈل/اختیاری کیٹلاگ کے مطابق حوالہ جات کو حل کرتا ہے۔ یہ مکمل Hermes انسٹالیشن ٹیسٹ نہیں ہے۔ CI صرف انحصار انسٹال کرنے کے لیے نیٹ ورک استعمال کرتا ہے؛ عام ٹیسٹ علمی APIs کو کال نہیں کرتے۔

CI لائیو اپ اسٹریم کینری توثیق کے ساتھ Linux x86_64 (Python 3.10–3.14)، Linux ARM64 (ubuntu-24.04-arm)، Ubuntu 26.04 پریویو کینری (ubuntu-26.04 اور ubuntu-26.04-arm)، Windows x86_64، Windows ARM64 (windows-11-arm)، macOS ARM64 (macos-latest)، اور macOS Intel (macos-15-intel) پر مکمل QA سوٹ چلاتا ہے۔ بنیادی ریلیز امیدوار نے 1165 مقامی ٹیسٹ پاس کیے۔ موجودہ مرمت کے نتائج اور کوریج کی حدود [درستگی کی مرمت کی دستاویز](../../docs/maintenance/correctness-repair-20261008.md) میں درج ہیں؛ ریموٹ شواہد ٹیسٹ کیے گئے HEAD کی الگ سے نشاندہی کرتے ہیں۔ `main` پر پش کرنے پر ایک الگ ٹیپ انٹیگریشن ورک فلو چلتا ہے: یہ `tests/upstream/provenance.json` میں درج پن کیے گئے Hermes چیک آؤٹ کو انسٹال کرتا ہے اور اس ریپوزٹری کے خلاف `tap add`، `search`، `install` اور `list` کی مشق کرتا ہے۔ درست ورژنز، چیکس اور حدود [آڈٹ دستاویز](../../docs/project-lineage-audit-20260920.md) میں درج ہیں۔

[tools/longtail/](../../tools/longtail/README.md) میں قطعی لانگ ٹیل فیکٹر جنریٹر موجود ہے: 4096 SHA256 سیڈڈ امیدوار، 30 منتخب منظرنامے اور مشین سے محسوب کردہ تصدیقی احاطے کی رپورٹ۔ v3 ماڈل صلاحیت کے خاندانوں (E01)، ریپوزٹری کی 14 حقیقی مہارتوں (E02)، اور ٹاسک کے اہداف (E03) کو الگ الگ شمار کرتا ہے۔ ہر منظرنامے میں ایک بنیادی مہارت، ایک معاون ٹاسک ہدف اور ہم آہنگ صلاحیتیں ہوتی ہیں؛ ہر مہارت کو اپنے اعلان کردہ بنیادی ہدف سمیت دو مختلف اہداف کے تحت کم از کم دو بار ظاہر ہونا چاہیے۔ مہارت کی ڈائریکٹری میں انحراف کی صورت میں تصدیق ناکام ہو جاتی ہے۔ معنوی توسیع (ٹاسک چینز، اوریکلز اور چلائے گئے ایونٹ کا انجیکشن) ایک الگ مرحلہ رہتی ہے؛ عوامل کا احاطہ ورک فلو کے چلنے کے احاطے کو ثابت نہیں کرتا۔

`scripts/scfabric/` سائنسی حساب کتاب اور شماریاتی آلات کی ایگزیکیوشن تہہ ہے: ہارڈویئر پروب، `dtype` گیٹس کے ساتھ بیک اینڈ کیٹلاگ، پانچ ورک لوڈ پروفائلز، عددی مساوات کی جانچ کے ساتھ جوڑے دار بینچ مارک، اور `ComputeReceipt`۔ اس مشین پر پہلے مرحلے کی پیمائشیں [docs/scientific-compute-fabric.md](../../docs/scientific-compute-fabric.md) میں درج ہیں؛ عملی اصول یہ ہے کہ ڈیفالٹ طور پر CPU استعمال کیا جائے اور ایکسلریٹر صرف رسید کی موجودگی میں چلایا جائے۔

## مقامی Agent کے ذریعے تحقیقی مقالے کا مطالعہ

`academic-research-kernel[research]==2.2.0` انسٹال کریں اور پیکیج شدہ ورک فلو ایکسپورٹ کریں:

```sh
academic-research-kernel research skill --output ./agent-skills/paper-research
```

Work یا کسی ہم آہنگ مقامی Agent کو ایکسپورٹ کردہ `SKILL.md` پڑھنے دیں، پھر اس سے کہیں:
“研究这篇论文及其补充材料，整理方法，核对能重算的关键数字，给我一份带出处的中文报告。”
صرف DOI، عوامی لنک یا مقامی فائل بنڈل فراہم کریں۔ دو مقالوں کی صورت میں، اسے ڈیٹا، طریقہ کار، تشخیصی شرائط اور نتائج کا موازنہ کرنے کا کہیں، اور یہ واضح کرنے کو کہیں کہ کون سے نتائج براہ راست قابل موازنہ ہیں۔ Agent اسی ٹاسک کے اندر اصل متن کا مطالعہ، امیدوار فیلڈز کی توثیق، حساب کتاب، کرنل میں شمولیت، رپورٹ کی تیاری اور ماخذ کی آزادانہ تصدیق اور توثیق کا عمل مکمل کرتا ہے۔ موجودہ MCP سطح اپنے 12 ٹولز برقرار رکھتی ہے؛ نیا آرکیسٹریشن CLI اور پورٹیبل مہارت میں موجود ہے۔

پروگرام کے حقیقی مراحل یہ ہیں:

```sh
academic-research-kernel research prepare INPUT --project PROJECT
academic-research-kernel research finish --project PROJECT --candidate CANDIDATE.json
academic-research-kernel research compare LEFT_PROJECT RIGHT_PROJECT --analysis COMPARISON.json --output OUTPUT
```

`prepare` کمانڈ مواد حاصل کر کے اسے مینی فیسٹ، ماخذ کے ہیشز اور متعین کردہ حصوں میں تجزیہ کرتی ہے۔ `finish` کمانڈ Agent کے تیار کردہ اخراج کی توثیق کرتی ہے اور موجودہ شماریاتی ٹولز کا استعمال کرتے ہوئے اہل t/p، دو گروپوں کے اثر کے حجم اور گنتی/فیصد کے دعووں کا دوبارہ حساب لگاتی ہے، پھر کرنل کی کیفیت اور چینی Markdown/HTML رپورٹس محفوظ کرتی ہے۔ `compare` کمانڈ قابل موازنہ شرائط کے بارے میں Agent کے صریح تجزیے کی توثیق کرتی ہے۔ یہ کمانڈز کوئی مستقل ریزیڈنٹ ماڈل شامل نہیں کرتیں: معنوی مطالعہ موجودہ Agent کی جانب سے [paper-research](../../skills/paper-research/SKILL.md) کی پیروی کرتے ہوئے کیا جاتا ہے۔ محفوظ کردہ اصل فائلیں اور اخراج کے اسنیپ شاٹس قطعی آف لائن ری پلے کی معاونت کرتے ہیں۔ نیٹ ورک سے حصول اور نیا معنوی مطالعہ الگ سے شناخت شدہ عوامل کے طور پر برقرار رہتے ہیں۔

## 2.0.1 درستگی کی مرمت اور ڈسٹری بیوشن کی تصدیق

پروڈکٹ ریلیز 2.0.1 میں شماریاتی دوبارہ حساب، مضامین کی واپسی کی نگرانی اور MCP سیشن کی درستگی کی مرمتیں شامل ہیں۔ عوامی ٹول `academic_recompute_statistics` اب t-ٹیسٹ کی p-قدروں اور دو گروپوں کے Cohen's d / Hedges' g کو ظاہر کرتا ہے۔ اعتماد کے وقفے (CI) اور OR/RR نچلی سطح کے Python فنکشنز کے طور پر برقرار رہتے ہیں۔ جب رپورٹ کی اعشاریہ درستگی اہم ہو تو `p_value_literal` (مثال کے طور پر `"1.0e-5"`) یا `p_value_decimals` فراہم کریں۔ لٹرل اقدار آخر میں آنے والے صفر کو محفوظ رکھتی ہیں؛ عددی ان پٹ صرف اپنی عددی نمائندگی برقرار رکھتے ہیں۔ متضاد درستگی کے ذرائع واضح طور پر ناکام ہو جاتے ہیں۔ راؤنڈ ہاف اپ موازنے میں نچلی راؤنڈنگ حد شامل ہوتی ہے اور اوپری حد خارج ہوتی ہے۔ ایک عام شماریاتی عدم مطابقت ایک کامیاب سائنسی نتیجہ ہے؛ غیر درست یا جزوی طور پر ناکام حساب کتاب `isError` سیٹ کرتے ہیں۔

مضمون کی واپسی (retraction) کی جانچ موجودہ `True`/`False`/`unknown` مشاہدے کو آخری معلوم (`last-known`) قدر سے الگ ریکارڈ کرتی ہے۔ سوال سے پہلے کی ایک مختصر ریزرویشن ایک ہی DOI کے مشاہدات کو ترتیب دیتی ہے اور دیگر DOI اپ ڈیٹس کو محفوظ رکھتی ہے۔ موجودہ مشاہدات اور تاریخی تصدیقات کے الگ الگ ورژن ہوتے ہیں: تاخیر سے ملنے والی درست تصدیق محفوظ شدہ تاریخ کو بہتر بنا سکتی ہے جبکہ نیا `unknown` موجودہ جانچ کے لیے واضح طور پر غیر مصدقہ رہتا ہے۔ ریگریشن چینز میں شامل HTTP فکسچرز کو ٹیسٹ ڈیٹا کے طور پر نشان زد کیا گیا ہے۔

MCP سرور `ping` کا جواب دیتا ہے، درست نوٹیفکیشنز (`notifications/cancelled` سمیت) پر خاموش رہتا ہے، اور غلط ان پٹ کے بعد بھی stdio سیشن کو فعال رکھتا ہے۔ سنکرونس نفاذ پیشگی منسوخی (preemptive cancellation) کا دعویٰ نہیں کرتا۔ پیغامات کی ہینڈلنگ [MCP پیغام معاہدے](https://modelcontextprotocol.io/specification/2024-11-05/basic/messages) اور [ping وضاحت](https://modelcontextprotocol.io/specification/2024-11-05/basic/utilities/ping) کی پیروی کرتی ہے۔

ایک الگ تھلگ ماحول کے ساتھ اس چیک آؤٹ کی ڈسٹری بیوشنز بنائیں اور ان کی تصدیق کریں:

```bash
python -m build
python -m twine check --strict dist/*
python scripts/package_acceptance.py --dist dist --uvx --source-checks --report package-acceptance.json
```

`--source-checks` آپشن چیک آؤٹ کے باہر امیدوار `sdist` کو بغیر کسی تبدیلی کے کھولتا ہے، `ARK_REPO` اور `ARK_SDIST` کو اس امیدوار پر سیٹ کرتا ہے، اور اس کے ٹیسٹ، جامد QA، قابل عمل کوڈ بلاکس اور i18n جانچ کو چلاتا ہے۔ وہیل اور `sdist` انسٹالیشنز ہر ایک نیا ماحول استعمال کرتی ہیں؛ `uvx` ایک آزاد کیشے کے ساتھ مقامی وہیل استعمال کرتا ہے۔ رپورٹ میں فن پاروں کے ہیشز اور انسٹال شدہ امپورٹ راستے ریکارڈ کیے جاتے ہیں۔ طے شدہ ہلکی پھلکی پنڈ/تازہ ترین Hermes جانچیں ٹیسٹ کیے گئے SHA کو آزادانہ طور پر رپورٹ کرتی ہیں۔ بیرونی معاہدے کی JSON اور جاب کا خلاصہ `healthy`، `degraded` اور `failed` کی اصطلاحات استعمال کرتا ہے؛ چھوڑے گئے پروبز واضح رہتے ہیں۔
