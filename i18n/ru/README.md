Детерминированное ядро управления состоянием научных исследований и верификации данных для исследовательских процессов с участием ИИ-агентов, не зависящее от конкретной среды исполнения. Система объединяет идентификацию исследовательских объектов, запись доказательств / подтверждения эмпирических данных, связи утверждений и доказательств (CEG) и пополняемый журнал исследовательских решений и отрицательных результатов через механизм загрузки и синтаксического анализа артефактов и универсальный сервер Model Context Protocol (MCP). Четырнадцать специализированных научных навыков формируют и используют проверенное исследовательское состояние при нативной поддержке Claude Code, Cursor, Codex, Gemini CLI и Hermes Agent. Область валидации и ограничения внешних сервисов зафиксированы в [материалах аудита](../../docs/kernel-architecture.md).

Автор: Junfu Shi (SJF, xngg1021), Hermes Agent. Действующее лицензионное предложение: [Source Lineage License 1.0](../../LICENSE).

## Быстрый старт

Запустите версию 2.2.0 с помощью [uv](https://docs.astral.sh/uv/getting-started/installation/):

```bash
uvx academic-research-kernel@2.2.0 mcp
```

В описании [релиза 2.2.0](https://github.com/xngg1021/academic-research-kernel/releases/tag/v2.2.0) приведены контрольные суммы пакетов и статус публикации. Собранный wheel-пакет также можно запустить локально командой `uvx --from ./academic_research_kernel-2.2.0-py3-none-any.whl academic-research-kernel mcp`. Поддерживаются версии Python 3.10–3.14; параметр `uvx --python 3.12` явно выбирает совместимый интерпретатор. Все 12 детерминированных инструментов, включая статистические модули, входят в базовую установку.

## Проверка установки

```bash
uvx academic-research-kernel@2.2.0 doctor
uvx academic-research-kernel@2.2.0 --version
```

Автономная диагностика проверяет зависимости, схемы данных и описания всех 12 инструментов. Дополнительные внешние сервисы могут оставаться ненастроенными. Используйте `doctor --json` для получения машиночитаемого вывода.

## Установка пакета

```bash
uv tool install academic-research-kernel==2.2.0
academic-research-kernel doctor
academic-research-kernel mcp
```

Пакет также можно установить через `pipx install academic-research-kernel==2.2.0` или `python -m pip install academic-research-kernel==2.2.0` в поддерживаемом виртуальном окружении. Профиль `[full]` добавляет библиотеки для расширенных вычислительных примеров; `[qa]` включает инструменты проверки репозитория, в том числе анализатор PDF. Профиль `[research]` устанавливает `pypdf==6.19.0` и `fonttools==4.65.0` для единообразного декодирования шрифтов PDF в чистых окружениях (оба пакета совместимы с Python 3.10). Структурированное чтение HTML/XML и ограниченное по размеру чтение DOCX/XLSX выполняются средствами стандартной библиотеки. Вычислительные бэкенды GPU и платные внешние сервисы остаются необязательными.

## Hermes

Убедитесь, что `uv` доступен в `PATH` процесса Hermes, после чего установите и явно активируйте переносимый плагин:

```bash
hermes plugins install xngg1021/academic-research-kernel --no-enable
hermes plugins enable academic-skills
```

Существующий идентификатор `academic-skills` сохранен для обратной совместимости и охватывает все 14 навыков, включая `paper-research`. Конфигурация `mcp.json` плагина вызывает `uv run --frozen --no-dev --no-editable` с Python 3.12 и файлом `uv.lock` репозитория, размещая изолированное окружение в `${PLUGIN_DATA}/runtime`. При первом запуске зависимости разворачиваются автоматически без заимствования пакетов Python из Hermes или операционной системы; для загрузки недостающих пакетов или интерпретатора потребуется доступ к сети. Прежний способ подключения отдельных навыков через tap по-прежнему поддерживается и описан ниже в разделе об интеграции.

## Академические стандарты и многопрофильная базовая линия

Стили библиографических ссылок, критерии научной отчетности и схемы метаданных определяются требованиями целевого журнала, научной организации, грантодателя, дисциплины и юрисдикции. В качестве международной основы репозиторий опирается на **ISO 690:2021** (Библиографические ссылки), **ISO 5127:2017** (Информационно-документационный словарь) и **W3C PROV** (Модель данных о происхождении), сочетая их с региональными профилями (например, GB/T 7714-2025 в материковом Китае, UNE-ISO 690:2024 в Испании, DIN ISO 690:2021 в Германии) и отраслевыми стандартами (APA 7-го изд., IEEE, ACM, Vancouver, Chicago, PRISMA 2020, ICMJE). Требования конкретного издания всегда имеют приоритет над профилями по умолчанию. Подробнее см. в документах [Архитектура академических стандартов](../../docs/standards/README.md) и [Руководство по естественной терминологии](../../docs/terminology/README.md).

Итоговое обновление целостности проверяет согласованность DOI и внешних идентификаторов, взаимную исключительность булевых флагов количественных вердиктов и единый контракт для структуры «вопросы, требующие проверки» между ядром и квитанциями загрузки. Полнота кэша восстанавливается по сохраненным исходным конвертам и нормализованным привязкам независимо от списков мутаций в квитанции; одновременное удаление записи и объявления кэша не позволяет пройти повторную проверку. См. [отчет о закрытии четырех блокирующих проблем](../../docs/kernel-architecture.md).

## Интеграция и переносимое использование

### 1. Universal Agent Plugins v1 и Model Context Protocol (MCP)
Репозиторий соответствует независимой от поставщика спецификации **Agent Plugins v1** (`../../plugin.json`) и предоставляет основные инструменты библиографической верификации и статистического пересчета через stdio-сервер **MCP** (`../../mcp.json` / `../../scripts/mcp_server.py`). Решение совместимо с Claude Code, Cursor, Gemini CLI и другими современными агентными средами. Несмотря на то что репозиторий носит имя `academic-research-kernel`, имя манифеста плагина `academic-skills` и псевдонимы конфигурации MCP сохраняются неизменными для обратной совместимости.

```bash
# Add as stdio MCP server in your agent harness
uvx academic-research-kernel mcp
```

### 2. Нативная установка в Hermes
В установленной среде Hermes выполните:

```bash
hermes skills tap add xngg1021/academic-research-kernel
hermes skills search academic-source-verification
hermes skills install xngg1021/academic-research-kernel/skills/academic-source-verification
```

Остальные навыки устанавливаются путем подстановки имени соответствующего каталога в полный идентификатор. Обычная команда tap обращается к основной ветке репозитория и устанавливает перечисленный выше набор навыков. Для проверки рабочей ветки до слияния переключитесь на нее локально и воспользуйтесь инструкцией по установке из локального каталога для вашей версии Hermes; не следует предполагать, что команда tap автоматически выбирает ветку запроса на слияние.

Связанные навыки, проверенные по базовому снимку upstream `245e48008fa814b3251f50755eb656bd9fb86cb1`: arxiv, grounded-citations, docx, pdf и manim-video. Пакеты huggingface-hub и llama-cpp входят в дополнительный каталог и могут требовать отдельной установки. Модули ocr-and-documents и pc-hardware-benchmark в указанном снимке отсутствовали и не являются зависимостями. Инструменты сессии и обработчики документов или браузера зависят от локальной конфигурации.

## Доступ к источникам данных

- Базовые запросы к OpenAlex можно выполнять анонимно в рамках уменьшенного дневного бюджета. Согласно документации на 2026-09-06, лимит составляет 0,10 долл. США в день без ключа и 1 долл. США в день с бесплатным ключом API при ограничении до 100 запросов в секунду. Стоимость зависит от типа запроса, поэтому доступ не является безлимитным. Дополнительный ключ сохраняется в переменной `OPENALEX_API_KEY`; рекомендуется использовать параметр `per_page` (не более 100) и курсорную пагинацию.
- Crossref предоставляет открытый доступ к метаданным с ограничением частоты запросов. Проверка связей обновления и сигналов Retraction Watch требует анализа DOI и направления связей; отсутствие записей само по себе не доказывает, что публикация не была отозвана или исправлена.
- Для работы с Unpaywall необходимо указать действующий контактный адрес электронной почты в `UNPAYWALL_EMAIL`. Отсутствие найденной ссылки не означает, что копии в открытом доступе не существует.
- arXiv, Europe PMC, PubMed E-utilities и DOAJ служат дополнительными источниками с собственными правилами использования и не вызываются в полном объеме при стандартном прогоне тестов. В Semantic Scholar действуют общие лимиты для анонимных обращений и отдельные квоты для ключей API; наличие доступа не гарантирует выдачу контекста цитирования.
- Scite, Dimensions, Scopus, Web of Science и сервисы детекции ИИ-текста являются необязательными внешними платформами. Перед обращением к ним проверьте права учетной записи, доступные эндпоинты и квоты; универсальный бесплатный тариф или фиксированная стоимость не гарантируются.

Дополнительные сведения приведены в документации по [аутентификации OpenAlex](https://help.openalex.org/api/authentication/), [бюджетам и стоимости запросов](https://help.openalex.org/api/llm-quick-reference/) и [фильтрам обновлений Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/).

## Детерминированная загрузка данных и публичное ядро

Подсистема загрузки и синтаксического анализа артефактов включает `ResearchArtifactEnvelope v1`, `ArtifactIngestionReceipt v1`, 15 адаптеров (для 14 навыков и резервного непрозрачного обработчика `opaque fallback`), а также 12 не сохраняющих состояние инструментов stdio MCP. Принятые квитанции загрузки связывают каждое сохраненное семантическое изменение по типу, идентификатору и каноническому хешу SHA-256: объекты исследования, записи графа утверждений и доказательств (CEG), записи журнала решений, вопросы, требующие проверки, физические квитанции и регистрации артефактов. При повторном воспроизведении из кэша эти обязательства проверяются независимо от хешей транспортных снимков. Пустые журналы считаются корректными, а сбой атомарного пакета не оставляет частичных изменений состояния.

Полномочия на доступ к содержимому источников происхождения задаются явно и передаются вне основного канала. Доверенные вызовы из Python передают `LineageVerificationContext` при воспроизведении сериализованных квитанций или снимков; вызовы через MCP могут передавать ограниченный объем байтов содержимого, но никогда не передают корневой каталог файловой системы хоста. Стандартный лимит объема содержимого составляет 10 МиБ; доверенный хост может явно разрешить более крупные артефакты при единой политике между источником и верификатором. Без подтвержденного доступа к содержимому статус `fully_verified` не может быть независимо воспроизведен и возвращает структурированный результат о недействительной проверке. Неструктурированный текст остается непрозрачным, расхождения мнений сохраняются видимыми, а принятие коммитов, закрытие или возобновление исследовательских маршрутов, маршрутизация и содержательные научные выводы остаются за исследователем.

Описание контрактов и правил совместимости приведено в [документе об архитектуре ядра](../../docs/kernel-architecture.md). Контрольные точки сборки и публикации зафиксированы в [руководстве по выпуску](../../docs/distribution-release.md). Файлы README на английском и упрощенном китайском языках поддерживаются в актуальном состоянии, а статус остальных переводов явно отражается в [манифесте синхронизации](../../docs/i18n/manifest.json). Идентификатор итогового кандидата, результаты CI на точном коммите и сводные материалы рецензирования записаны в [протоколе завершения](https://github.com/xngg1021/academic-research-kernel/pull/12#issuecomment-5754741342).

## Валидация и тестирование

Используйте изолированное окружение Python. Библиотеки времени выполнения зависят от конкретной задачи и не обязательно предустановлены в Hermes. Набор зависимостей для QA шире, чтобы обеспечить выполнение всех размеченных примеров:

```bash
python -m pip install -r requirements-qa.txt
python -m pip install 'torch>=2.5,<3' --index-url https://download.pytorch.org/whl/cpu
python scripts/qa.py
python -m pytest -q -rs tests
python scripts/i18n_sync.py --check
python scripts/verify_external_apis.py --output external-status.json --summary external-summary.md
git diff --check
```

Скрипт QA проверяет метаданные, локальные ссылки, отсутствие личных файловых путей и известных шаблонов секретов, синтаксис Python и размеченные исполняемые блоки кода. Каждый `smoke`-пример запускается без изменений в отдельном подпроцессе. Примеры построения графиков поддерживают переменную `PLOT_DIR` (по умолчанию `~/plots` с явным раскрытием пути), а во время тестов используют временный каталог. Неклассифицированные блоки Python отклоняются; блоки `fragment:` проходят синтаксическую проверку, но требуют именованных входных данных и не запускаются отдельно. Блоки `external-test:` выполняются только через ручную команду проверки внешних API, которая возвращает `0` при успешном прохождении настроенных проверок, `1` при ошибке кода, схемы или идентификации и `2` при недоступности сети, аутентификации или квоты; ненастроенные дополнительные сервисы получают статус `SKIP`.

Зафиксированные тесты проверки оформления навыков Hermes используются без изменения их правил для отдельных навыков. Глобальные проверки всего дистрибутива Hermes к данному репозиторию не применяются: тестовый контур проверяет четырнадцать навыков и разрешает ссылки относительно зафиксированного каталога встроенных и дополнительных пакетов. Это не заменяет полного теста установки Hermes. В среде CI сеть используется только для установки зависимостей, а обычные тесты проверок не обращаются к внешним научным API.

В CI полный набор проверок QA выполняется на платформах Linux x86_64 (Python 3.10–3.14), Linux ARM64 (`ubuntu-24.04-arm`), Ubuntu 26.04 preview canary (`ubuntu-26.04` и `ubuntu-26.04-arm`), Windows x86_64, Windows ARM64 (`windows-11-arm`), macOS ARM64 (`macos-latest`) и macOS Intel (`macos-15-intel`), включая регулярную canary-проверку совместимости с основной веткой upstream. Базовый исторический кандидат успешно прошел 1165 локальных теста. Актуальные результаты исправлений и границы тестового покрытия приведены в [отчете об исправлениях корректности](../../docs/maintenance/correctness-repair-20261008.md), где для внешних проверок отдельно указан протестированный коммит `HEAD`. Отдельный рабочий процесс интеграции tap запускается при отправке изменений в ветку `main`: он устанавливает зафиксированную ревизию Hermes из `tests/upstream/provenance.json` и проверяет операции `tap add`, `search`, `install` и `list` на этом репозитории. Точные версии, перечень проверок и ограничения описаны в [материалах аудита](../../docs/kernel-architecture.md).

В каталоге [tools/longtail/](../../tools/longtail/README.md) размещен детерминированный генератор редких факторных сценариев: 4096 кандидатов на основе зерна SHA-256, 30 отобранных сценариев и автоматически вычисляемый отчет о полноте проверки. Модель v3 раздельно учитывает семейства возможностей (E01), 14 фактических навыков репозитория (E02) и целевые задачи (E03). Каждому сценарию сопоставлены один основной навык, поддерживаемая цель задачи и совместимые возможности; каждый навык должен встречаться не менее двух раз в рамках двух различных целей, включая свою основную заявленную цель. При расхождении со структурой каталогов навыков проверка завершается ошибкой. Семантическое развертывание (цепочки задач, проверочные оракулы и инъекция исполняемых событий) выделено в отдельный этап: факторное покрытие само по себе не означает покрытия сквозного выполнения рабочих процессов.

Каталог `scripts/scfabric/` содержит набор инструментов для научных вычислений и статистики: модуль опроса оборудования, реестр бэкендов с ограничениями по типам данных (`dtype`), пять профилей вычислительной нагрузки, парный бенчмарк с допуском по численной эквивалентности и формирование `ComputeReceipt`. Результаты первичных измерений приведены в [docs/scientific-compute-fabric.md](../../docs/scientific-compute-fabric.md); базовое правило — использование ЦП по умолчанию и включение ускорителей только при наличии подтверждающей квитанции.

## Исследование научной статьи с помощью локального агента

Установите пакет `academic-research-kernel[research]==2.2.0` и экспортируйте встроенный рабочий процесс:

```sh
academic-research-kernel research skill --output ./agent-skills/paper-research
```

Поручите Work или другому совместимому локальному агенту прочитать экспортированный файл `SKILL.md`, после чего отправьте запрос:
“研究这篇论文及其补充材料，整理方法，核对能重算的关键数字，给我一份带出处的中文报告。”
Достаточно указать DOI, публичную ссылку или путь к локальному набору файлов. Для сопоставления двух работ попросите агента сравнить данные, методологию, условия оценки и результаты, пояснив, какие показатели допускают прямое сравнение. В рамках одной задачи агент последовательно выполнит чтение оригинала, проверку извлеченных кандидатов полей, статистический пересчет, загрузку в ядро, формирование отчета и независимую сверку с первоисточником. Существующий интерфейс MCP сохраняет свои 12 инструментов, а новая логика оркестрации реализована в CLI и переносимом навыке.

Основные программные этапы выполняются командами:

```sh
academic-research-kernel research prepare INPUT --project PROJECT
academic-research-kernel research finish --project PROJECT --candidate CANDIDATE.json
academic-research-kernel research compare LEFT_PROJECT RIGHT_PROJECT --analysis COMPARISON.json --output OUTPUT
```

Команда `prepare` получает и разбирает исходные материалы, формируя манифест, контрольные суммы файлов и привязанные текстовые сегменты. Команда `finish` проверяет подготовленную агентом структурированную выжимку и пересчитывает подходящие t-критерии и p-значения, величины эффекта для двух групп, а также количественные доли и проценты с помощью штатных статистических функций, после чего сохраняет состояние ядра и отчеты на китайском языке в форматах Markdown и HTML. Команда `compare` верифицирует явную оценку сопоставимости условий двух исследований, выполненную агентом. Эти команды не содержат встроенной резидентной языковой модели: смысловое чтение текста осуществляется текущим агентом в соответствии с инструкциями [paper-research](../../skills/paper-research/SKILL.md). Сохраненные исходные файлы и снимки извлечения обеспечивают детерминированное автономное воспроизведение, тогда как сетевая загрузка и повторное семантическое чтение фиксируются как отдельные операции.

## Исправления версии 2.0.1 и проверка дистрибутивов

Релиз 2.0.1 включает исправления точности статистических расчетов и обработки протокола. Публичный инструмент `academic_recompute_statistics` предоставляет расчет p-значений t-теста и показателей `d` Коэна / `g` Хеджеса для двух групп, тогда как расчет доверительных интервалов и отношений шансов или рисков (`OR/RR`) остается на уровне функций Python. Если важна точность представления в публикации, передайте `p_value_literal` (например, `"1.0e-5"`) или `p_value_decimals`. Строковые литералы сохраняют замыкающие нули, а числовые значения используют только стандартное числовое представление; при противоречии между источниками точности возвращается явная ошибка. При округлении по правилу `round-half-up` нижняя граница интервала включается, а верхняя исключается. Обычное статистическое расхождение с текстом статьи трактуется как корректный научный результат проверки, тогда как некорректные входные данные или сбои вычислений устанавливают флаг `isError`.

При проверке отзыва статей текущее наблюдение (`True`/`False`/`unknown`) записывается отдельно от последнего подтвержденного значения. Кратковременная блокировка перед запросом упорядочивает наблюдения по одному и тому же DOI и сохраняет обновления по другим DOI. Текущие наблюдения и исторические подтверждения имеют раздельное версионирование: запоздалое подтверждение может дополнить сохраненную историю, в то время как более поздний статус `unknown` остается явно помеченным как неподтвержденный для текущей проверки. Имитационные ответы HTTP в регрессионных цепочках явно маркируются как тестовые данные.

Сервер MCP отвечает на запросы `ping`, не отправляет ответов на корректные уведомления (включая `notifications/cancelled`) и сохраняет активность сессии stdio после некорректного ввода. Синхронная реализация не заявляет поддержки упреждающей отмены операций. Обработка сообщений соответствует [спецификации сообщений MCP](https://modelcontextprotocol.io/specification/2024-11-05/basic/messages) и [спецификации ping](https://modelcontextprotocol.io/specification/2024-11-05/basic/utilities/ping).

Сборка и приемка дистрибутивов текущей рабочей копии выполняются в изолированном окружении:

```bash
python -m build
python -m twine check --strict dist/*
python scripts/package_acceptance.py --dist dist --uvx --source-checks --report package-acceptance.json
```

Флаг `--source-checks` распаковывает проверяемый архив `sdist` без изменений вне рабочего дерева репозитория, устанавливает переменные `ARK_REPO` и `ARK_SDIST` на этот архив и запускает модульные тесты, статический анализ QA, проверку исполняемых блоков кода и синхронизации i18n. Установка из `wheel` и `sdist` проверяется в отдельных чистых окружениях, а `uvx` использует локальный `wheel` с изолированным кэшем. Итоговый отчет фиксирует контрольные суммы артефактов и фактические пути импорта модулей. Регулярные облегченные проверки совместимости с Hermes (`pinned` и `latest`) отдельно указывают проверенный коммит SHA. Внешние JSON-отчеты и сводки выполнения используют статусы `healthy`, `degraded` и `failed`, явно отмечая пропущенные проверки.
