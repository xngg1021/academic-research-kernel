نواة حتمية لإدارة حالة البحث الأكاديمي مخصصة لمسارات العمل البحثية المعتمدة على الوكلاء، ومستقلة عن بيئة التشغيل. توحد هذه المنظومة هوية كائنات البحث، وسجل الأدلة / التحقق التجريبي، والروابط بين الادعاءات والأدلة (CEG)، وسجل قرارات البحث والنتائج السلبية القابل للإلحاق فقط، وذلك عبر طبقة حتمية مسؤولة عن استيعاب وتحليل مصادر البحث وخادم قياسي لبروتوكول سياق النموذج (MCP). تعمل 14 مهارة بحثية متخصصة بوصفها منتجة ومستهلكة لحالة البحث المتحقق منها، مع دعم أصيل لبيئات Claude Code وCursor وCodex وGemini CLI وHermes Agent. تم توثيق نطاق التحقق وحدود الخدمات الخارجية في [تقرير التدقيق](../../docs/project-lineage-audit-20260920.md).

المؤلف: Junfu Shi (SJF, xngg1021)، Hermes Agent. العرض المرخص الحالي: [Source Lineage License 1.0](../../LICENSE).

## البدء السريع

شغّل الإصدار 2.2.0 باستخدام أداة [uv](https://docs.astral.sh/uv/getting-started/installation/):

```bash
uvx academic-research-kernel@2.2.0 mcp
```

يوثق [إصدار 2.2.0](https://github.com/xngg1021/academic-research-kernel/releases/tag/v2.2.0) بصمات التوزيع (hashes) وحالة النشر. يمكن أيضًا تشغيل حزمة wheel محليًا عبر الأمر `uvx --from ./academic_research_kernel-2.2.0-py3-none-any.whl academic-research-kernel mcp`. يدعم النظام إصدارات Python من 3.10 إلى 3.14؛ ويتيح الخيار `uvx --python 3.12` تحديد مفسر مدعوم بشكل صريح. تتضمن الحزمة الأساسية جميع الأدوات الحتمية الاثنتي عشرة، بما فيها مجموعة أدوات الحساب العلمي والإحصاء.

## التحقق من التثبيت

```bash
uvx academic-research-kernel@2.2.0 doctor
uvx academic-research-kernel@2.2.0 --version
```

يفحص التشخيص غير المتصل بالشبكة الاعتماديات البرمجية والمخططات (schemas) وتعريفات الأدوات الاثنتي عشرة كلها. يمكن ترك الخدمات الخارجية الاختيارية دون إعداد. استخدم `doctor --json` للحصول على مخرجات مقروءة آليًا.

## تثبيت الحزمة

```bash
uv tool install academic-research-kernel==2.2.0
academic-research-kernel doctor
academic-research-kernel mcp
```

بدلاً من ذلك، يمكنك التثبيت عبر `pipx install academic-research-kernel==2.2.0` أو `python -m pip install academic-research-kernel==2.2.0` داخل بيئة افتراضية مدعومة. تضيف المجموعة الاختيارية `[full]` مكتبات للأمثلة العلمية الموسعة؛ وتضيف `[qa]` أدوات التحقق من المستودع بما فيها محلل ملفات PDF. أما `[research]` فتضيف `pypdf==6.19.0` و`fonttools==4.65.0` لضمان فك ترميز خطوط PDF باتساق عبر التثبيتات النظيفة، وكلاهما يدعم Python 3.10. تعتمد قراءة HTML/XML المهيكلة وملفات DOCX/XLSX محدودة الحجم على المكتبة القياسية. تظل واجهات GPU والخدمات المدفوعة اختيارية.

## Hermes

ثبّت أداة uv بحيث تكون متاحة ضمن مسار العملية `PATH` الخاص بـ Hermes، ثم ثبّت الإضافة المحمولة وفعّلها صراحةً:

```bash
hermes plugins install xngg1021/academic-research-kernel --no-enable
hermes plugins enable academic-skills
```

يُحتفظ بالمعرف الحالي `academic-skills` لضمان التوافق، شاملاً 14 مهارة من بينها `paper-research`. يستدعي ملف `mcp.json` الخاص بالإضافة الأمر `uv run --frozen --no-dev --no-editable` باستخدام Python 3.12 وملف القفل `uv.lock` في المستودع؛ وتستقر بيئة التشغيل المستقلة داخل `${PLUGIN_DATA}/runtime`. تقوم الإضافة بتهيئة الاعتماديات عند الاستخدام الأول دون استعارة حزم Python الخاصة بـ Hermes أو النظام. يتطلب التشغيل الأول اتصالاً بالشبكة لجلب الحزم أو المفسر المفقود. يظل التثبيت القديم المقتصر على المهارات عبر `tap` مدعومًا في قسم التكامل والاستخدام المحمول أدناه.

## المعايير الأكاديمية والخط الأساسي متعدد الملفات

تعتمد أنماط التوثيق ومعايير الإبلاغ وعقود البيانات الوصفية على المجلة المستهدفة والمؤسسة والجهة الممولة والتخصص والاختصاص القضائي. يرسي المستودع معايير **ISO 690:2021** (المراجع الببليوغرافية)، و**ISO 5127:2017** (مفردات المعلومات والتوثيق)، و**W3C PROV** (نموذج بيانات المنشأ) كخطوط أساس دولية، إلى جانب الملفات الإقليمية (مثل GB/T 7714-2025 في الصين، وUNE-ISO 690:2024 في إسبانيا، وDIN ISO 690:2021 في ألمانيا) والمعايير التخصصية (APA 7th وIEEE وACM وVancouver وChicago وPRISMA 2020 وICMJE). وتكون الأولوية دائمًا لمتطلبات جهة النشر المستهدفة على الملفات الافتراضية. راجع [بنية المعايير الأكاديمية](../../docs/standards/README.md) و[دليل المصطلحات الطبيعية](../../docs/terminology/README.md).

يتحقق تحديث إصلاح النواة النهائي من اتساق معرفات DOI والمعرفات الخارجية، وعلامات الحكم الكمي المتنافية، والعقد المشترك بين النواة والإيصال الخاص بعناصر تتطلب المراجعة والتحقق. يُعاد بناء اكتمال ذاكرة التخزين المؤقت (cache) من مظاريف المصادر المحتفظ بها والارتباطات المطبّعة بشكل مستقل عن قوائم التعديلات في الإيصال؛ ولذلك فإن حذف سجل وإعلان ذاكرة التخزين المؤقت الخاصة به معًا لا يمكن أن ينتج إعادة تشغيل مقبولة. راجع [تقرير إغلاق العوائق الأربعة](../../docs/project-lineage-audit-20260920.md#four-blocker-successor--2026-09-21).

## التكامل والاستخدام المحمول

### 1. Universal Agent Plugins v1 & Model Context Protocol (MCP)
يتوافق هذا المستودع مع مواصفة **Agent Plugins v1** المحايدة للموردين (`../../plugin.json`) ويتيح أدوات التحقق الأكاديمي وإعادة الحساب الإحصائي عبر **خادم MCP** يعمل ببروتوكول stdio (`../../mcp.json` / `../../scripts/mcp_server.py`). وهو متوافق مع Claude Code وCursor وGemini CLI وأي إطار وكلاء حديث. (ملاحظة: رغم أن هوية المستودع هي `academic-research-kernel`، فإن اسم بيان الإضافة `academic-skills` والأسماء البديلة لإعدادات MCP تظل ثابتة لضمان التوافق مع الإصدارات السابقة.)

```bash
# Add as stdio MCP server in your agent harness
uvx academic-research-kernel mcp
```

### 2. التثبيت الأصيل في Hermes
من داخل بيئة تثبيت Hermes، نفّذ الأوامر التالية:

```bash
hermes skills tap add xngg1021/academic-research-kernel
hermes skills search academic-source-verification
hermes skills install xngg1021/academic-research-kernel/skills/academic-source-verification
```

ثبّت بقية المهارات باستبدال اسم الدليل في المعرف الكامل. يقرأ أمر `tap` الاعتيادي الفرع الافتراضي، لذا فإن التثبيت الجديد يوفر مجموعة المهارات المذكورة أعلاه. ولغرض فحص فرع عمل قبل الدمج، استخرج ذلك الفرع محليًا واتبع تعليمات التثبيت من مجلد محلي الخاصة بإصدار Hermes المثبت لديك. لا تفترض أن أمر `tap` يختار فرع طلب سحب تلقائيًا.

تم التحقق من المهارات المدمجة ذات الصلة عند الإيداع المصدري `245e48008fa814b3251f50755eb656bd9fb86cb1`: arxiv وgrounded-citations وdocx وpdf وmanim-video. وتوجد حزمتا huggingface-hub وllama-cpp في الفهرس الاختياري وقد تتطلبان تثبيتًا مستقلاً. أما ocr-and-documents وpc-hardware-benchmark فلم تكونا ضمن تلك اللقطة وليستا من الاعتماديات. تعتمد أدوات الجلسة وواجهات المستندات أو المتصفح على الإعدادات المحلية.

## الوصول إلى مصادر البيانات

- يمكن تشغيل استعلامات OpenAlex الأساسية دون تعريف هوية ضمن ميزانية يومية صغيرة. تحدد الوثائق المحدثة في 2026-09-06 ميزانية 0.10 دولار/يوم للاستخدام المجهول و1 دولار/يوم عند استخدام مفتاح API مجاني، مع سقف 100 طلب/ثانية. تختلف التكلفة باختلاف نوع الاستعلام، ولا يُعد هذا وصولاً غير محدود. خزّن المفتاح الاختياري في المتغير `OPENALEX_API_KEY`، واستخدم `per_page` (بحد أقصى 100) والتصفح بالمؤشر (cursor pagination).
- يتيح Crossref وصولاً عامًا للبيانات الوصفية مع تنظيم معدل الطلبات. تتطلب علاقات التحديث وإشارات Retraction Watch فحص معرف DOI واتجاه الرابط؛ ولا يعني غياب السجل أن الورقة البحثية غير متأثرة.
- يتطلب Unpaywall بريدًا إلكترونيًا حقيقيًا للتواصل في المتغير `UNPAYWALL_EMAIL`. ولا يثبت عدم العثور على مسار أنه لا توجد نسخة وصول مفتوح (OA).
- تُعد arXiv وEurope PMC وPubMed E-utilities وDOAJ مصادر تكميلية تخضع لسياساتها الخاصة، ولا تشغل الاختبارات الافتراضية جميع هذه المصادر. يفرض Semantic Scholar حدودًا مشتركة للاستخدام المجهول وحدودًا منفصلة لمفاتيح API؛ ولا يضمن الوصول إلى الواجهة توفر سياق الاستشهادات النصي.
- تُعد Scite وDimensions وScopus وWeb of Science ومنتجات كشف النصوص المولدة بالذكاء الاصطناعي خدمات خارجية اختيارية. تحقق من صلاحيات الحساب وحقوق API والحصص المتاحة قبل الاستخدام؛ إذ لا توجد طبقة مجانية شاملة أو تسعير ثابت مضمون.

راجع [توثيق مصادقة OpenAlex](https://help.openalex.org/api/authentication/)، و[الميزانيات وتكاليف الاستعلام](https://help.openalex.org/api/llm-quick-reference/)، و[مرشحات تحديث Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/).

## الاستيعاب الحتمي والنواة العامة

توفر طبقة استيعاب وتحليل مصادر البحث مخططي `ResearchArtifactEnvelope v1` و`ArtifactIngestionReceipt v1`، و15 محولاً (المهارات الـ 14 بالإضافة إلى المسار الاحتياطي غير المهيكل opaque fallback)، و12 أداة MCP عديمة الحالة عبر stdio. تربط إيصالات الاستيعاب المقبولة كل تغيير دلالي محتفظ به حسب النوع والهوية وبصمة SHA-256 القياسية: الكائنات، وسجلات CEG، وسجلات قرارات البحث، وعناصر تتطلب المراجعة والتحقق، والإيصالات المادية، وتسجيلات المصادر. تتحقق عملية إعادة تشغيل ذاكرة التخزين المؤقت من هذه الالتزامات بشكل مستقل عن بصمات لقطات النقل. وتُعد السجلات الفارغة صالحة، كما لا تترك الدفعات الذرية الفاشلة أي حالة جزئية.

تُمنح صلاحية قراءة محتوى النسب بشكل صريح وخارج النطاق (out of band). يمرر مستدعو Python الموثوقون كائن `LineageVerificationContext` عند إعادة تشغيل الإيصالات أو اللقطات المتسلسلة؛ بينما يمكن لمستدعي MCP تقديم بايتات محتوى محدودة الحجم فقط، ولا يُسمح أبدًا بتمرير جذر نظام الملفات للمضيف. تبلغ ميزانية المحتوى الافتراضية 10 MiB؛ ويمكن للمضيف الموثوق التصريح صراحةً بمصادر أكبر حجمًا تحت نفس سياسة المنتج والمدقق. وبدون صلاحية الوصول للمحتوى، لا يمكن إعادة إنتاج ادعاء يحمل الحالة `fully_verified` بصورة مستقلة، فيُرجع النظام نتيجة تحقق غير صالحة مهيكلة. تظل النصوص غير المهيكلة غير شفافة، وتبقى الآراء المعارضة مرئية، ويحتفظ الباحثون بالتحكم الكامل في الاعتماد، وإيقاف المسارات، وإعادة فتحها، والتوجيه، وإصدار أحكام الصحة العلمية.

راجع [وثيقة معمارية النواة](../../docs/kernel-architecture.md) للاطلاع على العقود وقواعد التوافق. تم توثيق نقاط فحص التوزيع والنشر في [دليل الإصدار](../../docs/distribution-release.md). نسختا README بالإنجليزية والصينية المبسطة محدثتان بالكامل؛ بينما تُعرض حالات الترجمات الأخرى بوضوح في [بيان المزامنة](../../docs/i18n/manifest.json). وتُسجل هوية المرشح النهائي، ونتائج التكامل المستمر (CI) على رأس الفرع الدقيق، والمراجعات التراكمية وأدلة الدمج في [سجل الإغلاق](https://github.com/xngg1021/academic-research-kernel/pull/12#issuecomment-5754741342).

## التحقق والاختبار (Validation)

استخدم بيئة Python مخصصة. تعتمد مكتبات وقت التشغيل على طبيعة المهمة وليس مضمونًا تثبيتها مسبقًا في Hermes. أما اعتماديات ضمان الجودة (QA) فهي أوسع نطاقًا لضمان إمكانية تشغيل جميع الأمثلة الموسومة:

```bash
python -m pip install -r requirements-qa.txt
python -m pip install 'torch>=2.5,<3' --index-url https://download.pytorch.org/whl/cpu
python scripts/qa.py
python -m pytest -q -rs tests
python scripts/i18n_sync.py --check
python scripts/verify_external_apis.py --output external-status.json --summary external-summary.md
git diff --check
```

يتحقق فحص QA من البيانات الوصفية، والمراجع، وأنماط المسارات الشخصية أو المفاتيح السرية المعروفة، وصحة بناء جملة Python، وكتل الأكواد القابلة للتنفيذ الموسومة. يعمل كل مثال فحص سريع (smoke test) دون تعديل في عملية فرعية جديدة. تقبل أمثلة الرسم البياني المتغير `PLOT_DIR` (الافتراضي `~/plots` مع توسيع المسار صراحةً)، وتستخدم الاختبارات مجلدًا مؤقتًا. تُرفض كتل أكواد Python غير المصنفة؛ بينما تُفحص كتل `fragment:` نحويًا لكنها تتطلب مدخلات مسماة ولا تُنفذ منفردة. وتعمل كتل `external-test:` فقط عبر الأمر الخارجي اليدوي، الذي يُرجع 0 عند اجتياز الفحوص المعدة، و1 عند فشل الكود أو المخطط أو الهوية، و2 عند عدم توفر النقل أو المصادقة أو الحصة؛ بينما تبقى الخدمات الاختيارية غير المعدة في حالة SKIP.

تُعاد الاستفادة من اختبارات تأليف مهارات Hermes المثبتة دون تغيير قواعدها لكل مهارة. لا تنطبق فحوص التوزع الشامل للحزمة المصدرية الكاملة على هذا المستودع؛ إذ يفحص إطار الاختبار لدينا أربع عشرة مهارة ويحل المراجع مقابل الفهرس المدمج والاختياري المثبت. ولا يُعد هذا اختبار تثبيت كامل لنظام Hermes. يستخدم نظام CI الشبكة لتثبيت الاعتماديات فقط؛ ولا تستدعي الاختبارات الاعتيادية واجهات برمجة التطبيقات الأكاديمية.

يشغّل نظام CI حزمة QA الكاملة عبر بيئات Linux x86_64 (بإصدارات Python 3.10–3.14)، وLinux ARM64 (ubuntu-24.04-arm)، وإصدار المعاينة Ubuntu 26.04 canary (ubuntu-26.04 وubuntu-26.04-arm)، وWindows x86_64، وWindows ARM64 (windows-11-arm)، وmacOS ARM64 (macos-latest)، وmacOS Intel (macos-15-intel)، مع فحص توافق مباشر (canary) مع المستودع الأصل. اجتاز المرشح الأساسي للإصدار 1165 اختبارًا محليًا. وتُسجل نتائج الإصلاح الحالية وحدود التغطية في [تقرير إصلاح الصحة](../../docs/maintenance/correctness-repair-20261008.md)، بينما تحدد الأدلة البعيدة رمز HEAD المختبر بشكل منفصل. كما يعمل مسار تكامل `tap` منفصل عند الدفع إلى الفرع الرئيسي `main`، حيث يثبت نسخة Hermes المحددة في `tests/upstream/provenance.json` ويختبر أوامر `tap add` و`search` و`install` و`list` على هذا المستودع. التفاصيل الدقيقة للإصدارات والفحوص والقيود موثقة في [تقرير التدقيق](../../docs/project-lineage-audit-20260920.md).

يحتوي الدليل [tools/longtail/](../../tools/longtail/README.md) على مولد عوامل الحالات النادرة (long-tail) الحتمي: 4096 مرشحًا مولدًا ببذرة SHA256، و30 سيناريو مختارًا، وتقرير تغطية التحقق محسوبًا آليًا. يحصي النموذج v3 عائلات القدرات (E01)، والمهارات الأربع عشرة الفعلية في المستودع (E02)، وأهداف المهام (E03) كلًا على حدة. يرتبط كل سيناريو بمهارة أساسية واحدة، وهدف مهمة مدعوم، وقدرات متوافقة؛ ويجب أن تظهر كل مهارة مرتين على الأقل تحت هدفين مختلفين، بما في ذلك هدفها الأساسي المعلن. يؤدي أي انحراف في دليل المهارات إلى فشل التحقق. ويظل التوسيع الدلالي (سلاسل المهام، ومعايير التحقق، وحقن الأحداث المنفذة) مرحلة منفصلة؛ فتغطية العوامل لا تثبت تغطية التنفيذ الفعلي لمسار العمل.

يمثل الدليل `scripts/scfabric/` طبقة التنفيذ الخاصة بمجموعة أدوات الحساب العلمي والإحصاء: مسبار العتاد، وفهرس الواجهات الخلفية المزود ببوابات أنواع البيانات (`dtype`)، وخمسة ملفات تعريف لأحمال العمل، واختبارات الأداء المقترنة بفحص التكافؤ العددي، وإيصال الحساب `ComputeReceipt`. توجد قياسات الجولة الأولى على هذا الجهاز في [docs/scientific-compute-fabric.md](../../docs/scientific-compute-fabric.md)؛ والقاعدة العملية المتبعة هي استخدام المعالج المركزي (CPU) افتراضيًا، وعدم تفعيل المسرعات إلا بوجود إيصال تحقق.

## دراسة ورقة بحثية باستخدام وكيل محلي (Agent)

ثبّت الحزمة `academic-research-kernel[research]==2.2.0` وصدّر مسار العمل المدمج:

```sh
academic-research-kernel research skill --output ./agent-skills/paper-research
```

دع بيئة Work أو أي وكيل محلي متوافق يقرأ ملف `SKILL.md` المصدّر، ثم اطلب منه:
“研究这篇论文及其补充材料，整理方法，核对能重算的关键数字，给我一份带出处的中文报告。”
اكتفِ بتزويد معرف DOI أو رابط عام أو حزمة ملفات محلية. وفي حالة المقارنة بين ورقتين بحثيتين، اطلب منه مقارنة البيانات، والمنهجية، وشروط التقييم، والنتائج، مع توضيح الجوانب القابلة للمقارنة المباشرة. يواصل الوكيل ضمن المهمة نفسها قراءة النص الأصلي، والتحقق من المرشحات المستخرجة، وإعادة الحساب، والاستيعاب في النواة، وتوليد التقرير، وإجراء التحقق المستقل والتأكيد للمصادر. يحتفظ سطح MCP الحالي بأدواته الاثنتي عشرة؛ بينما تستقر طبقة التنسيق الجديدة في واجهة سطر الأوامر (CLI) والمهارة المحمولة.

مراحل البرنامج الفعلية هي:

```sh
academic-research-kernel research prepare INPUT --project PROJECT
academic-research-kernel research finish --project PROJECT --candidate CANDIDATE.json
academic-research-kernel research compare LEFT_PROJECT RIGHT_PROJECT --analysis COMPARISON.json --output OUTPUT
```

يقوم الأمر `prepare` بجلب المواد وتحليلها إلى بيان ملفات (manifest)، وبصمات مصادر، ومقاطع نصية محددة الموقع. ويتحقق الأمر `finish` من المخرجات التي استخرجها الوكيل ويعيد حساب ادعاءات اختبار t وقيم p المؤهلة، وحجم الأثر لمجموعتين، والأعداد والنسب المئوية باستخدام الأدوات الإحصائية المتاحة، ثم يحفظ حالة النواة وتقارير Markdown/HTML باللغة الصينية. أما الأمر `compare` فيتحقق من التقييم الصريح الذي يقدمه الوكيل لشروط قابلية المقارنة. لا تدمج هذه الأوامر نموذجًا مقيمًا داخليًا: إذ يتولى الوكيل الحالي عملية القراءة الدلالية باتباع تعليمات مهارة [paper-research](../../skills/paper-research/SKILL.md). وتدعم الملفات الأصلية ولقطات الاستخراج المحفوظة إعادة التشغيل الحتمية دون اتصال بالشبكة. كما يظل الجلب الشبكي والقراءة الدلالية الجديدة عمليتين مميزتين بشكل منفصل.

## إصلاحات الصحة في الإصدار 2.0.1 والتحقق من التوزيع

يتضمن إصدار المنتج 2.0.1 إصلاحات الصحة والدقة الخاصة بإعادة الحساب الإحصائي، وتتبع سحب الأبحاث، وإدارة جلسات MCP. تكشف الأداة العامة `academic_recompute_statistics` عن قيم p لاختبار t ومقاييس Cohen's d وHedges' g لمجموعتين. بينما تظل فترات الثقة (CI) ونسب الأرجحية والمخاطر (OR/RR) دوال Python في المستوى الأدنى. مرّر المعامل `p_value_literal` (مثل `"1.0e-5"`) أو `p_value_decimals` عندما تكون دقة الأرقام العشرية في التقرير مهمة. تحافظ القيم النصية الحرفية على الأصفار اللاحقة؛ في حين تحتفظ المدخلات الرقمية بتمثيلها العددي فقط. وتؤدي مصادر الدقة المتعارضة إلى فشل صريح. تشمل مقارنات التقريب النصف للأعلى (round-half-up) الحد الأدنى للتقريب وتستبعد الحد الأعلى. ويُعد عدم التطابق الإحصائي العادي نتيجة علمية ناجحة؛ أما الحسابات غير الصالحة أو الفاشلة جزئيًا فتضبط العلامة `isError`.

تسجل فحوص سحب الأبحاث (retraction) المشاهدة الحالية (`True`/`False`/`unknown`) بشكل منفصل عن آخر قيمة معروفة (`last-known`). يقوم حجز قصير قبل الاستعلام بترتيب المشاهدات الخاصة بنفس معرف DOI مع الحفاظ على تحديثات المعرفات الأخرى. وتمتلك المشاهدات الحالية والتأكيدات التاريخية إصدارات منفصلة: إذ يمكن لتأكيد متأخر أن يحسن السجل التاريخي المحتفظ به، بينما تظل حالة `unknown` الأحدث موسومة صراحةً بأنها غير متحقق منها للفحص الحالي. وتُوسم بيانات HTTP الثابتة في سلاسل اختبارات الانحدار بأنها بيانات اختبارية.

يستجيب خادم MCP لأمر `ping`، ويلتزم الصمت إزاء الإشعارات الصالحة (بما فيها `notifications/cancelled`)، ويحافظ على بقاء جلسة stdio نشطة بعد تلقي مدخلات غير صالحة. لا يعلن التنفيذ المتزامن عن دعم الإلغاء الاستباقي (preemptive cancellation). ويتبع التعامل مع الرسائل [عقد رسائل MCP](https://modelcontextprotocol.io/specification/2024-11-05/basic/messages) و[مواصفة ping](https://modelcontextprotocol.io/specification/2024-11-05/basic/utilities/ping).

ابنِ حزم التوزيع الخاصة بهذه النسخة وتحقق منها داخل بيئة معزولة:

```bash
python -m build
python -m twine check --strict dist/*
python scripts/package_acceptance.py --dist dist --uvx --source-checks --report package-acceptance.json
```

يقوم الخيار `--source-checks` بفك ضغط حزمة المصدر المرشحة `sdist` دون تعديل خارج شجرة المستودع، ويضبط المتغيرين `ARK_REPO` و`ARK_SDIST` للإشارة إلى تلك الحزمة المرشحة، ثم يشغّل اختباراتها، وفحص QA الثابت، وكتل الأكواد القابلة للتنفيذ، وفحص تزامن اللغات (i18n). تستخدم عمليات تثبيت `wheel` و`sdist` بيئة نظيفة مستقلة لكل منها؛ وتستخدم أداة `uvx` ملف `wheel` المحلي مع ذاكرة تخزين مؤقت مستقلة. يسجل التقرير بصمات الحزم ومسارات الاستيراد الفعلية بعد التثبيت. كما تُبلغ فحوص Hermes المجدولة الخفيفة عن بصمة SHA المختبرة لكل من النسخة المثبتة (pinned) والأحدث (latest) بشكل مستقل. وتستخدم ملفات JSON للعقود الخارجية وملخصات المهام الحالات `healthy` و`degraded` و`failed`؛ مع بقاء الفحوص المتخطاة موسومة بوضوح.
