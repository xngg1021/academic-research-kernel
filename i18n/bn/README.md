# academic-research-kernel (bn)

এজেন্ট-নির্ভর গবেষণা কর্মপ্রবাহের জন্য প্ল্যাটফর্ম-নিরপেক্ষ ও সুনির্দিষ্ট (deterministic) গবেষণা-অবস্থা ব্যবস্থাপনা কাঠামো। এটি সুনির্দিষ্ট গবেষণা উপকরণ অন্তর্ভুক্তি ও পার্সিং ব্যবস্থার পাশাপাশি সর্বজনীন Model Context Protocol (MCP) সার্ভারের মাধ্যমে গবেষণা বস্তুর পরিচয়, অভিজ্ঞতালব্ধ প্রমাণ / যাচাইকরণ রেকর্ড, ত্রিপক্ষীয় দাবি ও প্রমাণের সংযোগ (CEG) এবং সংযোজন-নির্ভর গবেষণা সিদ্ধান্ত ও ব্যর্থ প্রচেষ্টার লগকে একত্রিত করে। ১৪টি বিশেষায়িত একাডেমিক দক্ষতা যাচাইকৃত গবেষণা অবস্থার উৎপাদক ও ভোক্তা হিসেবে কাজ করে এবং Claude Code, Cursor, Codex, Gemini CLI ও Hermes Agent-এর সাথে সরাসরি সামঞ্জস্য বজায় রাখে। যাচাইকরণের পরিধি এবং বাহ্যিক পরিষেবার সীমাবদ্ধতা [নিরীক্ষা প্রতিবেদনে](../../docs/project-lineage-audit-20260920.md) লিপিবদ্ধ আছে।

লেখক: Junfu Shi (SJF, xngg1021), Hermes Agent। বর্তমান লাইসেন্সের পরিধি: [Source Lineage License 1.0](../../LICENSE)।

## দ্রুত শুরু

[uv](https://docs.astral.sh/uv/getting-started/installation/) ব্যবহার করে সংস্করণ 2.1.0 চালান:

```bash
uvx academic-research-kernel@2.1.0 mcp
```

[2.1.0 রিলিজ](https://github.com/xngg1021/academic-research-kernel/releases/tag/v2.1.0) ডিস্ট্রিবিউশন হ্যাশ এবং প্রকাশনার অবস্থা সংরক্ষণ করে। রিলিজ হুইলটি স্থানীয়ভাবে `uvx --from ./academic_research_kernel-2.1.0-py3-none-any.whl academic-research-kernel mcp` কমান্ড দিয়েও চালানো যায়। Python 3.10–3.14 সমর্থিত; `uvx --python 3.12` সুনির্দিষ্টভাবে একটি সমর্থিত ইন্টারপ্রেটার নির্বাচন করে। বৈজ্ঞানিক গণনা ও পরিসংখ্যানগত টুলসেট সহ সমস্ত ১২টি সুনির্দিষ্ট টুল মূল ইনস্টলেশনেই অন্তর্ভুক্ত রয়েছে।

## ইনস্টলেশন যাচাই

```bash
uvx academic-research-kernel@2.1.0 doctor
uvx academic-research-kernel@2.1.0 --version
```

অফলাইন ডায়াগনস্টিক প্রক্রিয়াটি ডিপেন্ডেন্সি, স্কিমা এবং ১২টি টুলের সংজ্ঞা পরীক্ষা করে। ঐচ্ছিক বাহ্যিক পরিষেবাগুলো কনফিগার না করলেও সমস্যা হয় না। মেশিন-পাঠযোগ্য আউটপুটের জন্য `doctor --json` ব্যবহার করুন।

## প্যাকেজ ইনস্টল

```bash
uv tool install academic-research-kernel==2.1.0
academic-research-kernel doctor
academic-research-kernel mcp
```

বিকল্পভাবে, সমর্থিত ভার্চুয়াল এনভায়রনমেন্টের ভেতরে `pipx install academic-research-kernel==2.1.0` অথবা `python -m pip install academic-research-kernel==2.1.0` দিয়ে ইনস্টল করা যাবে। `[full]` অপশনটি বর্ধিত বৈজ্ঞানিক উদাহরণের জন্য অতিরিক্ত লাইব্রেরি যোগ করে; `[qa]` অপশনটি পিডিএফ পার্সারসহ রিপোজিটরি যাচাইকরণ টুল যোগ করে। `[research]` অপশনটি নতুন ইনস্টলেশনে পিডিএফ ফন্ট ডিকোডিং সুসংগত রাখতে `pypdf==6.19.0` এবং `fonttools==4.65.0` যুক্ত করে; দুটিই Python 3.10 সমর্থন করে। কাঠামোগত HTML/XML এবং নির্ধারিত আকারের DOCX/XLSX পাঠের কাজে স্ট্যান্ডার্ড লাইব্রেরি ব্যবহৃত হয়। GPU ব্যাকএন্ড এবং অর্থপ্রদত্ত পরিষেবাগুলো ঐচ্ছিক থাকে।

## Hermes

Hermes প্রসেসের PATH-এ uv ইনস্টল থাকার পর পোর্টেবল প্লাগইনটি ইনস্টল ও সক্রিয় করুন:

```bash
hermes plugins install xngg1021/academic-research-kernel --no-enable
hermes plugins enable academic-skills
```

পূর্ববর্তী সামঞ্জস্য বজায় রাখতে `academic-skills` নামটি অপরিবর্তিত রাখা হয়েছে, যার অধীনে `paper-research` সহ মোট ১৪টি দক্ষতা রয়েছে। প্লাগইনের `mcp.json` ফাইলটি Python 3.12 এবং রিপোজিটরির `uv.lock` ব্যবহার করে `uv run --frozen --no-dev --no-editable` আহ্বান করে; এর নিজস্ব রানটাইম পরিবেশ `${PLUGIN_DATA}/runtime`-এর অধীনে থাকে। প্রথমবার ব্যবহারের সময় এটি Hermes বা সিস্টেমের Python প্যাকেজ ধার না করেই স্বয়ংক্রিয়ভাবে প্রয়োজনীয় ডিপেন্ডেন্সি প্রস্তুত করে নেয়। অনুপস্থিত প্যাকেজ বা ইন্টারপ্রেটার ডাউনলোডের জন্য প্রথমবার ইন্টারনেট সংযোগ প্রয়োজন। শুধু দক্ষতা ইনস্টল করার পুরনো tap পদ্ধতিটি নিচের ইন্টিগ্রেশন ও পোর্টেবল ব্যবহার অনুচ্ছেদে এখনও সমর্থিত।

## সোর্স কোড থেকে চালানো

```bash
git clone https://github.com/xngg1021/academic-research-kernel.git
cd academic-research-kernel
uv sync --frozen --no-dev --no-editable
uv run --frozen --no-dev --no-editable academic-research-kernel doctor
uv run --frozen --no-dev --no-editable python scripts/mcp_server.py
```

ডিপেন্ডেন্সি শ্রেণিবিন্যাস, পুনরুৎপাদন পদ্ধতি, রিলিজ পরিচয়, প্রকাশনা চেকপয়েন্ট এবং যাচাইকরণের পরিধি জানতে [ডিস্ট্রিবিউশন ও রিলিজ নির্দেশিকা](../../docs/distribution-release.md) দেখুন।

## একাডেমিক মানদণ্ড ও বহু-প্রোফাইল ভিত্তিরেখা

উদ্ধৃতি শৈলী, প্রতিবেদনের মানদণ্ড এবং মেটাডেটা চুক্তি লক্ষ্য জার্নাল, প্রতিষ্ঠান, অর্থায়নকারী সংস্থা, বিষয় এবং বিচারব্যবস্থার ওপর নির্ভর করে। রিপোজিটরিটি আন্তর্জাতিক ভিত্তিরেখা হিসেবে **ISO 690:2021** (গ্রন্থপঞ্জি সংক্রান্ত রেফারেন্স), **ISO 5127:2017** (তথ্য ও ডকুমেন্টেশন শব্দভাণ্ডার) এবং **W3C PROV** (উৎস ডেটা মডেল) নির্ধারণ করে; এর পাশাপাশি আঞ্চলিক প্রোফাইল (যেমন মূল ভূখণ্ড চীনে GB/T 7714-2025, স্পেনে UNE-ISO 690:2024, জার্মানিতে DIN ISO 690:2021) এবং বিষয়ভিত্তিক মানদণ্ড (APA 7th, IEEE, ACM, Vancouver, Chicago, PRISMA 2020, ICMJE) সমর্থন করে। লক্ষ্য প্রকাশনা সংস্থার শর্তাবলি সর্বদা ডিফল্ট প্রোফাইলের ওপর প্রাধান্য পায়। বিস্তারিত জানতে [একাডেমিক মানদণ্ড আর্কিটেকচার](../../docs/standards/README.md) এবং [স্বাভাবিক পরিভাষা নির্দেশিকা](../../docs/terminology/README.md) দেখুন।

সর্বশেষ কার্নেল যাচাইকরণ সংস্করণে DOI/আইডেন্টিফায়ার সামঞ্জস্য, বিপরীতমুখী পরিমাণগত সিদ্ধান্তের ফ্ল্যাগ এবং কার্নেল ও রসিদের অভিন্ন পর্যালোচনা প্রয়োজন এমন আইটেম চুক্তি যাচাই করা হয়েছে। রসিদের পরিবর্তন তালিকা থেকে স্বাধীনভাবে, সংরক্ষিত উৎস এনভেলপ এবং প্রমিত বাইন্ডিং থেকে ক্যাশের সম্পূর্ণতা পুনর্গঠন করা হয়; কোনো রেকর্ড এবং তার ক্যাশ ঘোষণা একসাথে মুছে ফেললেও গ্রহণযোগ্য রিপ্লে তৈরি করা সম্ভব নয়। বিস্তারিত জানতে [চারটি প্রতিবন্ধকতা নিষ্পত্তি প্রতিবেদন](../../docs/project-lineage-audit-20260920.md#four-blocker-successor--2026-09-21) দেখুন।

### 2. Hermes-এ নেটিভ ইনস্টলেশন
Hermes ইনস্টলেশন পরিবেশ থেকে নিচের কমান্ডগুলো চালান:

```bash
hermes skills tap add xngg1021/academic-research-kernel
hermes skills search academic-source-verification
hermes skills install xngg1021/academic-research-kernel/skills/academic-source-verification
```

পূর্ণ আইডেন্টিফায়ারে ডিরেক্টরির নাম পরিবর্তন করে বাকি দক্ষতাগুলো ইনস্টল করুন। সাধারণ tap কমান্ড ডিফল্ট ব্রাঞ্চ পড়ে, তাই নতুন tap করলে উপরের দক্ষতা সেটটি ইনস্টল হয়। মার্জ করার আগে কোনো কাজের ব্রাঞ্চ পরীক্ষা করতে চাইলে স্থানীয়ভাবে সেই ব্রাঞ্চ চেকআউট করুন এবং ইনস্টল করা Hermes সংস্করণের স্থানীয় ফোল্ডার ইনস্টলেশন নির্দেশিকা অনুসরণ করুন। ধরে নেবেন না যে tap কমান্ড স্বয়ংক্রিয়ভাবে কোনো পুল রিকোয়েস্ট ব্রাঞ্চ নির্বাচন করবে।

আপস্ট্রিম কমিট `245e48008fa814b3251f50755eb656bd9fb86cb1`-এ যাচাইকৃত সম্পর্কিত বান্ডিল দক্ষতাগুলো হলো: arxiv, grounded-citations, docx, pdf, manim-video। huggingface-hub এবং llama-cpp ঐচ্ছিক ক্যাটালগে রয়েছে এবং আলাদাভাবে ইনস্টল করার প্রয়োজন হতে পারে। ocr-and-documents এবং pc-hardware-benchmark সেই স্ন্যাপশটে পাওয়া যায়নি এবং সেগুলো কোনো ডিপেন্ডেন্সি নয়। সেশন টুল এবং ডকুমেন্ট/ব্রাউজার ব্যাকএন্ড স্থানীয় কনফিগারেশনের ওপর নির্ভর করে।

## ডেটা-উৎসে প্রবেশাধিকার

- OpenAlex-এর মৌলিক কুয়েরিগুলো ছোট দৈনিক বাজেটের আওতায় বেনামে চালানো যায়। 2026-09-06 তারিখের ডকুমেন্টেশন অনুযায়ী বেনামে প্রতিদিন $0.10 এবং বিনামূল্যের API কী ব্যবহার করলে প্রতিদিন $1 বাজেট ও প্রতি সেকেন্ডে সর্বোচ্চ ১০০টি অনুরোধের সীমা রয়েছে। কুয়েরির ধরনভেদে খরচ ভিন্ন হয়; এটি অসীম অ্যাক্সেস নয়। ঐচ্ছিক কী `OPENALEX_API_KEY`-তে সংরক্ষণ করুন এবং `per_page` (সর্বোচ্চ ১০০) ও কার্সর পেজিনেশন ব্যবহার করুন।
- Crossref হার নিয়ন্ত্রণের (throttling) মাধ্যমে সর্বজনীন মেটাডেটা অ্যাক্সেস দেয়। আপডেট সম্পর্ক এবং Retraction Watch সংকেতের জন্য DOI ও দিকনির্দেশ যাচাই করা আবশ্যক; কোনো রেকর্ড না থাকা প্রমাণ করে না যে গবেষণাপত্রটি প্রভাবিত হয়নি।
- Unpaywall ব্যবহারের জন্য `UNPAYWALL_EMAIL`-এ একটি প্রকৃত যোগাযোগের ইমেইল থাকা প্রয়োজন। কোনো অবস্থান খুঁজে না পাওয়া প্রমাণ করে না যে ওপেন অ্যাক্সেস (OA) কপি নেই।
- arXiv, Europe PMC, PubMed E-utilities এবং DOAJ নিজস্ব নীতিমালাসহ পরিপূরক উৎস। ডিফল্ট পরীক্ষায় এগুলোর সব কটি চালানো হয় না। Semantic Scholar-এ যৌথ বেনামী সীমা এবং আলাদাভাবে বরাদ্দকৃত কী সীমা রয়েছে; API অ্যাক্সেস থাকলেই উদ্ধৃতির প্রাসঙ্গিক পাঠ্য (citation context) পাওয়ার নিশ্চয়তা থাকে না।
- Scite, Dimensions, Scopus, Web of Science এবং AI-শনাক্তকরণ পণ্যগুলো ঐচ্ছিক বাহ্যিক পরিষেবা। ব্যবহারের আগে বর্তমান অ্যাকাউন্ট/API অধিকার এবং কোটা যাচাই করে নিন; সর্বজনীন ফ্রি টিয়ার বা নির্দিষ্ট মূল্যের কোনো প্রতিশ্রুতি দেওয়া হয় না।

বিস্তারিত জানতে [OpenAlex প্রমাণীকরণ](https://help.openalex.org/api/authentication/), [বাজেট ও কুয়েরি খরচ](https://help.openalex.org/api/llm-quick-reference/), এবং [Crossref আপডেট ফিল্টার](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/) দেখুন।

## সুনির্দিষ্ট অন্তর্ভুক্তি ও পাবলিক কার্নেল

গবেষণা উপকরণ অন্তর্ভুক্তি ও পার্সিং স্তরটি `ResearchArtifactEnvelope v1`, `ArtifactIngestionReceipt v1`, ১৫টি অ্যাডাপ্টার (১৪টি দক্ষতা এবং একটি ওপেক ফলব্যাক opaque fallback), এবং ১২টি স্টেটলেস stdio MCP টুল সরবরাহ করে। গৃহীত রসিদগুলো সংরক্ষিত প্রতিটি অর্থগত পরিবর্তনকে ধরন, পরিচয় এবং ক্যানোনিকাল SHA-256 দ্বারা আবদ্ধ করে: অবজেক্ট, CEG রেকর্ড, সিদ্ধান্ত লগ রেকর্ড, পর্যালোচনা প্রয়োজন এমন আইটেম, ভৌত রসিদ এবং আর্টিফ্যাক্ট নিবন্ধন। ক্যাশ রিপ্লে প্রক্রিয়া ট্রান্সপোর্ট স্ন্যাপশট হ্যাশ থেকে স্বাধীনভাবে সেই প্রতিশ্রুতিগুলো পরীক্ষা করে। খালি লগ বৈধ; ব্যর্থ অ্যাটমিক ব্যাচ কোনো আংশিক অবস্থা রেখে যায় না।

বংশপরম্পরা কন্টেন্টের কর্তৃত্ব সুস্পষ্ট এবং আউট-অফ-ব্যান্ড। বিশ্বস্ত Python কলাররা সিরিয়ালাইজড রসিদ বা স্ন্যাপশট রিপ্লে করার সময় `LineageVerificationContext` পাস করে; MCP কলাররা কেবল নির্ধারিত সীমার কন্টেন্ট বাইট সরবরাহ করতে পারে, কখনোই হোস্ট ফাইলসিস্টেম রুট নয়। ডিফল্ট কন্টেন্ট বাজেট ১০ MiB; উৎপাদক ও যাচাইকারীর অভিন্ন নীতির অধীনে বিশ্বস্ত হোস্ট সুস্পষ্টভাবে বড় আর্টিফ্যাক্ট অনুমোদন করতে পারে। কন্টেন্ট কর্তৃত্ব ছাড়া কোনো `fully_verified` দাবি স্বাধীনভাবে পুনরুৎপাদন করা যায় না এবং তা একটি কাঠামোগত অকার্যকর যাচাইকরণ ফলাফল ফেরত দেয়। অকাঠামোগত গদ্য অপরিবর্তিত (opaque) থাকে, ভিন্নমত দৃশ্যমান থাকে এবং কমিট, পথ বন্ধ করা, পুনরায় খোলা, রাউটিং ও সত্যতা নির্ধারণের নিয়ন্ত্রণ গবেষকদের হাতেই থাকে।

চুক্তি ও সামঞ্জস্যের নিয়মের জন্য [কার্নেল আর্কিটেকচার নথি](../../docs/kernel-architecture.md) দেখুন। ডিস্ট্রিবিউশন ও প্রকাশনা চেকপয়েন্টগুলো [রিলিজ নির্দেশিকায়](../../docs/distribution-release.md) নথিবদ্ধ আছে। ইংরেজি এবং সরলীকৃত চীনা README হালনাগাদ রয়েছে; অন্যান্য অনুবাদের অবস্থা [ম্যানিফেস্টে](../../docs/i18n/manifest.json) সুস্পষ্টভাবে উল্লেখ করা হয়েছে। চূড়ান্ত ক্যান্ডিডেট পরিচয়, সঠিক-HEAD CI, ক্রমপুঞ্জিত পর্যালোচনা এবং মার্জ প্রমাণ [সমাপ্তি লেজারে](https://github.com/xngg1021/academic-research-kernel/pull/12#issuecomment-5754741342) সংরক্ষিত আছে।

## যাচাইকরণ (Validation)

একটি পৃথক Python পরিবেশ ব্যবহার করুন। রানটাইম লাইব্রেরিগুলো কাজের ধরনের ওপর নির্ভরশীল এবং Hermes-এ আগে থেকেই ইনস্টল থাকার নিশ্চয়তা নেই। চিহ্নিত সমস্ত উদাহরণ যেন চালানো যায় সেজন্য QA ডিপেন্ডেন্সির পরিধি আরও বিস্তৃত:

```bash
python -m pip install -r requirements-qa.txt
python -m pip install 'torch>=2.5,<3' --index-url https://download.pytorch.org/whl/cpu
python scripts/qa.py
python -m pytest -q -rs tests
python scripts/i18n_sync.py --check
python scripts/verify_external_apis.py --output external-status.json --summary external-summary.md
git diff --check
```

QA মেটাডেটা, রেফারেন্স, ব্যক্তিগত পাথ/পরিচিত গোপন কী প্যাটার্ন, Python সিনট্যাক্স এবং চিহ্নিত এক্সিকিউটেবল কোড ব্লক যাচাই করে। প্রতিটি স্মোক উদাহরণ একটি নতুন সাবপ্রসেসে অপরিবর্তিত অবস্থায় চলে। প্লট উদাহরণগুলো `PLOT_DIR` গ্রহণ করে (ডিফল্ট `~/plots`, সুস্পষ্টভাবে প্রসারিত); পরীক্ষায় একটি অস্থায়ী ডিরেক্টরি ব্যবহৃত হয়। অশ্রেণিবদ্ধ Python কোড ব্লক প্রত্যাখ্যান করা হয়; `fragment:` ব্লকগুলোর সিনট্যাক্স পরীক্ষা করা হয় কিন্তু সেগুলোর জন্য নামযুক্ত ইনপুট প্রয়োজন হয় এবং সেগুলো এককভাবে চালানো হয় না। `external-test:` ব্লকগুলো কেবল ম্যানুয়াল বাহ্যিক কমান্ডের মাধ্যমে চলে। কনফিগার করা পরীক্ষা সফল হলে এটি 0, কোড/স্কিমা/পরিচয় ব্যর্থতায় 1 এবং ট্রান্সপোর্ট/প্রমাণীকরণ/কোটা অনুপলব্ধতায় 2 রিটার্ন করে; কনফিগার না করা ঐচ্ছিক পরিষেবাগুলো SKIP অবস্থায় থাকে।

পিন করা Hermes অথরিং টেস্টগুলো প্রতি-দক্ষতার নিয়ম পরিবর্তন না করেই পুনর্ব্যবহার করা হয়। আপস্ট্রিম সম্পূর্ণ-ডিস্ট্রিবিউশন পপুলেশন পরীক্ষা এই tap-এর ক্ষেত্রে প্রযোজ্য নয়; আমাদের টেস্ট হারনেস ১৪টি দক্ষতা পরীক্ষা করে এবং পিন করা বান্ডিল/ঐচ্ছিক ক্যাটালগের বিপরীতে রেফারেন্স মীমাংসা করে। এটি সম্পূর্ণ Hermes ইনস্টলেশন পরীক্ষা নয়। CI কেবল ডিপেন্ডেন্সি ইনস্টল করতে নেটওয়ার্ক ব্যবহার করে; সাধারণ পরীক্ষায় একাডেমিক API কল করা হয় না।

CI Linux x86_64 (Python 3.10–3.14), Linux ARM64 (ubuntu-24.04-arm), Ubuntu 26.04 প্রিভিউ ক্যানারি (ubuntu-26.04 ও ubuntu-26.04-arm), Windows x86_64, Windows ARM64 (windows-11-arm), macOS ARM64 (macos-latest) এবং macOS Intel (macos-15-intel) জুড়ে লাইভ আপস্ট্রিম ক্যানারি যাচাইকরণসহ সম্পূর্ণ QA স্যুট চালায়। বেসলাইন রিলিজ ক্যান্ডিডেট ১১৬৫টি স্থানীয় পরীক্ষায় উত্তীর্ণ হয়েছে। বর্তমান সংশোধন ফলাফল এবং কভারেজ সীমা [সঠিকতা মেরামত নথিতে](../../docs/maintenance/correctness-repair-20261008.md) লিপিবদ্ধ আছে; রিমোট প্রমাণ পরীক্ষিত HEAD-কে আলাদাভাবে চিহ্নিত করে। main ব্রাঞ্চে পুশ করা হলে একটি পৃথক tap ইন্টিগ্রেশন ওয়ার্কফ্লো চলে: এটি `tests/upstream/provenance.json`-এ লিপিবদ্ধ পিন করা Hermes চেকআউট ইনস্টল করে এবং এই রিপোজিটরির বিপরীতে `tap add`, `search`, `install` ও `list` পরীক্ষা করে। সঠিক সংস্করণ, পরীক্ষা এবং সীমাবদ্ধতা [নিরীক্ষা প্রতিবেদনে](../../docs/project-lineage-audit-20260920.md) রয়েছে।

[tools/longtail/](../../tools/longtail/README.md)-এ রয়েছে সুনির্দিষ্ট লং-টেইল ফ্যাক্টর জেনারেটর: ৪০৯৬টি SHA256-সিডেড ক্যান্ডিডেট, ৩০টি নির্বাচিত দৃশ্যপট এবং মেশিনে গণনাকৃত যাচাইকরণ কভারেজ রিপোর্ট। v3 মডেলটি সক্ষমতা পরিবার (E01), রিপোজিটরির ১৪টি প্রকৃত দক্ষতা (E02) এবং কাজের লক্ষ্যগুলোকে (E03) আলাদাভাবে গণনা করে। প্রতিটি দৃশ্যপটে একটি প্রধান দক্ষতা, একটি সমর্থিত লক্ষ্য এবং সামঞ্জস্যপূর্ণ সক্ষমতা থাকে; প্রতিটি দক্ষতাকে তার ঘোষিত মূল লক্ষ্যসহ অন্তত দুটি ভিন্ন লক্ষ্যের অধীনে কমপক্ষে দুইবার উপস্থিত থাকতে হয়। দক্ষতা-ডিরেক্টরির বিচ্যুতি ঘটলে যাচাইকরণ ব্যর্থ হয়। অর্থগত সম্প্রসারণ (টাস্ক চেইন, ওরাকল এবং এক্সিকিউটেড ইভেন্ট ইনজেকশন) একটি পৃথক ধাপ হিসেবে থাকে; ফ্যাক্টর কভারেজ কর্মপ্রবাহের এক্সিকিউশন কভারেজ প্রমাণ করে না।

`scripts/scfabric/` হলো বৈজ্ঞানিক গণনা ও পরিসংখ্যানগত টুলসেট-এর এক্সিকিউশন স্তর: হার্ডওয়্যার প্রোব, `dtype` গেটসহ ব্যাকএন্ড ক্যাটালগ, পাঁচটি ওয়ার্কলোড প্রোফাইল, প্যারিটি যাচাইসহ পেয়ার্ড বেঞ্চমার্ক এবং `ComputeReceipt`। এই মেশিনে প্রথম রাউন্ডের পরিমাপ [docs/scientific-compute-fabric.md](../../docs/scientific-compute-fabric.md)-এ রয়েছে; সাধারণ নিয়ম হলো ডিফল্টভাবে CPU ব্যবহার করা এবং শুধুমাত্র রসিদ থাকলেই অ্যাক্সিলারেটর ব্যবহার করা।

## স্থানীয় Agent দিয়ে গবেষণাপত্র বিশ্লেষণ

`academic-research-kernel[research]==2.1.0` ইনস্টল করুন এবং প্যাকেজকৃত কর্মপ্রবাহটি এক্সপোর্ট করুন:

```sh
academic-research-kernel research skill --output ./agent-skills/paper-research
```

Work বা অন্য কোনো সামঞ্জস্যপূর্ণ স্থানীয় Agent-কে এক্সপোর্ট করা `SKILL.md` ফাইলটি পড়তে দিন, তারপর বলুন:
“研究这篇论文及其补充材料，整理方法，核对能重算的关键数字，给我一份带出处的中文报告。”
শুধুমাত্র DOI, পাবলিক লিংক অথবা স্থানীয় ফাইল বান্ডিল দিন। দুটি গবেষণাপত্রের ক্ষেত্রে সেগুলোর ডেটা, পদ্ধতি, মূল্যায়নের শর্ত এবং ফলাফল তুলনা করতে বলুন এবং কোন ফলাফলগুলো সরাসরি তুলনাযোগ্য তা ব্যাখ্যা করতে বলুন। Agent একই কাজের ভেতরে মূল পাঠ্য পড়া, ক্যান্ডিডেট যাচাই, গণনা, কার্নেলে অন্তর্ভুক্তি, প্রতিবেদন তৈরি এবং স্বাধীন যাচাইকরণ ও নিশ্চিতকরণ সম্পন্ন করবে। বিদ্যমান MCP ইন্টারফেসে ১২টি টুল অক্ষুণ্ণ রয়েছে; নতুন অর্কেস্ট্রেশন যুক্ত হয়েছে CLI এবং পোর্টেবল দক্ষতায়।

প্রোগ্রামের প্রকৃত ধাপগুলো হলো:

```sh
academic-research-kernel research prepare INPUT --project PROJECT
academic-research-kernel research finish --project PROJECT --candidate CANDIDATE.json
academic-research-kernel research compare LEFT_PROJECT RIGHT_PROJECT --analysis COMPARISON.json --output OUTPUT
```

`prepare` কমান্ডটি উপাদান সংগ্রহ ও পার্স করে ম্যানিফেস্ট, সোর্স হ্যাশ এবং চিহ্নিত অংশে রূপান্তর করে। `finish` কমান্ডটি Agent-এর তৈরি করা তথ্য নিষ্কাশন যাচাই করে এবং বিদ্যমান পরিসংখ্যান টুল ব্যবহার করে প্রযোজ্য t/p, দুই-গ্রুপের প্রভাবের আকার এবং গণনা/শতাংশের দাবিগুলো পুনর্গণনা করে, এরপর কার্নেল অবস্থা এবং চীনা Markdown/HTML প্রতিবেদন সংরক্ষণ করে। `compare` কমান্ডটি তুলনাযোগ্য শর্তাবলি সম্পর্কে Agent-এর সুস্পষ্ট মূল্যায়ন যাচাই করে। এই কমান্ডগুলো কোনো স্থায়ী রেসিডেন্ট মডেল যুক্ত করে না: অর্থগত পাঠের কাজটি বর্তমান Agent নিজেই [paper-research](../../skills/paper-research/SKILL.md) অনুসরণ করে সম্পন্ন করে। সংরক্ষিত মূল ফাইল এবং নিষ্কাশন স্ন্যাপশট সুনির্দিষ্ট অফলাইন রিপ্লে সমর্থন করে। নেটওয়ার্ক থেকে সংগ্রহ এবং নতুন অর্থগত পাঠ পৃথক অপারেশন হিসেবে চিহ্নিত থাকে।

## 2.0.1 সঠিকতা মেরামত ও ডিস্ট্রিবিউশন যাচাইকরণ

পণ্য রিলিজ 2.0.1-এ পরিসংখ্যানগত পুনর্গণনা, প্রত্যাহার পর্যবেক্ষণ এবং MCP সেশনের সঠিকতা মেরামতগুলো অন্তর্ভুক্ত রয়েছে। পাবলিক `academic_recompute_statistics` টুলটি t-টেস্টের p-মান এবং দুই-গ্রুপের Cohen's d / Hedges' g প্রকাশ করে। কনফিডেন্স ইন্টারভ্যাল (CI) এবং OR/RR নিম্ন-স্তরের Python ফাংশন হিসেবে থাকে। প্রতিবেদনের দশমিক সূক্ষ্মতা গুরুত্বপূর্ণ হলে `p_value_literal` (উদাহরণস্বরূপ `"1.0e-5"`) অথবা `p_value_decimals` প্রদান করুন। লিটারেল মানগুলো শেষের শূন্য সংরক্ষণ করে; সংখ্যাসূচক ইনপুট কেবল তার সংখ্যাসূচক রূপটি ধরে রাখে। পরস্পরবিরোধী সূক্ষ্মতা উৎস থাকলে তা সুস্পষ্টভাবে ব্যর্থ হয়। রাউন্ড-হাফ-আপ তুলনায় নিচের রাউন্ডিং সীমানা অন্তর্ভুক্ত থাকে এবং উপরের সীমানা বাদ থাকে। সাধারণ পরিসংখ্যানগত অমিল একটি সফল বৈজ্ঞানিক ফলাফল হিসেবে গণ্য হয়; অকার্যকর বা আংশিক ব্যর্থ গণনার ক্ষেত্রে `isError` সেট হয়।

গবেষণাপত্র প্রত্যাহার (retraction) পরীক্ষায় বর্তমান `True`/`False`/`unknown` পর্যবেক্ষণকে সর্বশেষ-জানা (`last-known`) মান থেকে আলাদাভাবে রেকর্ড করা হয়। কুয়েরির আগের একটি সংক্ষিপ্ত রিজার্ভেশন একই-DOI পর্যবেক্ষণগুলোকে ক্রমানুসারে সাজায় এবং অন্য DOI-এর আপডেট সংরক্ষণ করে। বর্তমান পর্যবেক্ষণ এবং ঐতিহাসিক নিশ্চিতকরণের সংস্করণ আলাদা থাকে: দেরিতে আসা বৈধ নিশ্চিতকরণ সংরক্ষিত ইতিহাসকে উন্নত করতে পারে, যখন নতুন কোনো `unknown` বর্তমান পরীক্ষার জন্য সুস্পষ্টভাবে অযাচাইকৃত থাকে। রিগ্রেশন চেইনের HTTP ফিক্সচারগুলো পরীক্ষার ডেটা হিসেবে চিহ্নিত।

MCP সার্ভার `ping`-এর উত্তর দেয়, বৈধ নোটিফিকেশনের (`notifications/cancelled` সহ) ক্ষেত্রে নীরব থাকে এবং ভুল ইনপুটের পরও stdio সেশন সচল রাখে। সিনক্রোনাস ইমপ্লিমেন্টেশন প্রিএম্পটিভ বাতিলের দাবি করে না। বার্তা ব্যবস্থাপনা [MCP মেসেজ চুক্তি](https://modelcontextprotocol.io/specification/2024-11-05/basic/messages) এবং [ping স্পেসিফিকেশন](https://modelcontextprotocol.io/specification/2024-11-05/basic/utilities/ping) অনুসরণ করে।

একটি বিচ্ছিন্ন পরিবেশে এই চেকআউটের ডিস্ট্রিবিউশনগুলো বিল্ড ও যাচাই করুন:

```bash
python -m build
python -m twine check --strict dist/*
python scripts/package_acceptance.py --dist dist --uvx --source-checks --report package-acceptance.json
```

`--source-checks` অপশনটি চেকআউটের বাইরে ক্যান্ডিডেট `sdist`-কে অপরিবর্তিতভাবে আনপ্যাক করে, `ARK_REPO` ও `ARK_SDIST`-কে সেই ক্যান্ডিডেটে সেট করে এবং এর টেস্ট, স্ট্যাটিক QA, এক্সিকিউটেবল কোড ব্লক ও i18n পরীক্ষা চালায়। হুইল এবং `sdist` ইনস্টলেশন প্রতিটি একটি নতুন পরিবেশ ব্যবহার করে; `uvx` স্বাধীন ক্যাশসহ স্থানীয় হুইল ব্যবহার করে। প্রতিবেদনে আর্টিফ্যাক্ট হ্যাশ এবং ইনস্টলকৃত ইমপোর্ট পাথ সংরক্ষিত থাকে। নির্ধারিত হালকা পিনড/লেটেস্ট Hermes পরীক্ষাগুলো পরীক্ষিত SHA আলাদাভাবে রিপোর্ট করে। বাহ্যিক চুক্তির JSON এবং জব সামারিতে `healthy`, `degraded` ও `failed` ব্যবহৃত হয়; বাদ দেওয়া প্রোবগুলো সুস্পষ্ট থাকে।
