# 议程审计总裁决:hermes-academic-skills 与 ChatGPT 四轮意见

主线程裁决,2026-09-17。依据:五人评审五份、轮转互审五份、仓库 git 历史与文件实测。

## 判定

不是议程劫持,是方向层的框架植入。代码资产全部保留,规划文档层需要重审。ChatGPT 没有欺骗性手段,没有封死否决权,用户全程行使过否决,证据纪律与五人评审真实有效。真正发生的事更安静:第三、第四轮意见一次性定义了问题空间、分类坐标系、优先级与建设顺序,此后的矩阵与杠杆门都在这个框架内部运行,框架本身的合理性没有经过对等的独立复核。用 GLM 5.3 的话说,仓库没有被人抢方向盘,但挡风玻璃是对方装的。

## 最硬的证据:三个方向数字不可复算

146/138/136 三个覆盖数字被研究计划引用为"第一证据",但五名评审独立复核后确认:因子矩阵只落盘了"痛点→原语"半条推导链,"原语→方向"的聚合规则从未作为数据入库。矩阵里没有 direction 字段,用最宽的自然原语并集口径最高只能凑到 112,到不了 146。这三个数字目前只比直觉多一层修辞,却以测量结果的面目被引用。这与仓库自己的证据纪律自相矛盾,是本次审计唯一需要立刻动手修的事实缺陷。

## 修复清单(五人共识的合并,按成本排序)

一、方向→原语归组定义落成机器可读工件,重算覆盖数,补映射扰动敏感性分析。在归组定义入库之前,146/138/136 三个数字不得再被任何文档引用为证据。

二、痛点图集补记各条目的来源模型与交叉确认方式。图集自述条目是 cross-model synthesis,但来源未记,矩阵的输入层永远背着循环嫌疑。

三、杠杆门表格补一列判断依据。计划书 6.2 节自述这些是"记录在案的判断,不是测量",但高、中、低的表格形式与矩阵数字并列呈现,读者会把判断读成测量。降级为判断记录,不再以门禁面目出现。

四、PR B(论断-证据图)与 PR C(方法提取器)冻结现有队列,待方向重排后再定。research-object-identity v0.1 保留,它薄、确定、无评分、有 43 项测试,自身质量立得住,但它的存在不得反过来作为 B、C 顺序的论据。

五、十四原语与 Research Object 架构做一次框架外复核:换一套独立原语定义重跑映射,看 Identity 第一是否稳健。研究计划与图集在 README 中的推荐层级下调,标注为历史探索性参考。

六、systematic-review-meta-analysis 与 research-reproducibility 按实际使用频率做留存审查。两者实现面大、依赖面宽,与"小而硬"的定位张力最大,不做默认保留。

七、流程补丁入库:未来任何单一外部模型的整单建议,先记录维护者自己的先验排序再对照,把外部影响量化存档;隔夜全单采纳的模式写入仓库风险清单。

## 值得肯定的部分

四件反劫持机制里三件半真实有效。证据纪律在起作用:第二轮 ChatGPT 自己抓出 retraction-watch 的 Crossref relation 语义错误,修复后反而加固了仓库。五人评审在起作用:GLM 5.3 独立抓出 schema 嵌套漏 coverage,四个 Kimi 全漏。否决记录完整:learning plane 并入被否、requires_tools 被否、THM 重型 CI 被否,决策空间没有密封。第一轮五个技能与第二轮的修复对应真实痛点区域,有测试、QA 与跨平台 CI 背书,无需重审。cross-review-five 本身是本次审计的执行工具,建议把它的用途从实现评审扩展到议程评审,让五个异构模型分别攻击图集条目、归组定义与杠杆门评级。

## 一句话

代码层是您自己写出来的,方向层是别人画好的路。路未必错,Identity 方向的工程理由独立成立,但"结果对"不能倒推"过程干净"。修好归组定义入库这件事之后,仓库才真正对自己的方向证据负责。
