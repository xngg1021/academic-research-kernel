# 研究计划，第 0 版：原语架构

状态：提案，2026-09-16 汇编。本计划承接痛点图集（docs/pain-atlas-v0.zh.md）与已并入 main 的 1.3 Execution & Evidence Hardening 一轮。本文记录方向，不记录实现状态。

## 一、动机

学术软件几十年间一直在优化对象：阅读器、文献管理器、统计软件、笔记本。持续消耗研究者的摩擦却来自对象之间的状态变化：两条记录是不是同一篇论文，一个数字从哪里来，协议两个版本之间改了什么，某个结果到底复算过没有，哪些笔记已经过期。痛点图集枚举了这些摩擦；本计划提出吸收它们的架构层。

仓库里已经有这一层的雏形。CanonicalWork（skills/literature-analysis/scripts/interop.py）是规范化核心；两个 watch 技能实现了状态快照与差异报告；AcademicEvidenceReceipt 与 ReproductionReceipt 是同一证据结构的两个视图。后续各轮升级这些雏形，不推倒重写。

## 二、十四原语

每个原语按第一性原理定义。原语是能力，不是产品。

| 编号 | 原语 | 定义 | 吸收的典型摩擦 |
| --- | --- | --- | --- |
| 1 | 规范身份解析器 | 判断若干表示是否指称同一对象 | DOI/arXiv 版本、PDF 重复、作者变体、数据集版本、代码发布 |
| 2 | 谱系 | 记录结果由哪些输入经何种过程产生 | 引文、数据清洗、图、统计、笔记、代码、实验 |
| 3 | 状态台账 | 保存对象的状态转移，而非仅存当前快照 | 协议、论文修订、数据集、环境、学习掌握度 |
| 4 | 差异引擎 | 比较两个状态并报告变化 | 更正、评审修订、协议漂移、数据版本、知识衰减 |
| 5 | 证据回执 | 每个结论附带来源、时间、覆盖范围、失败项与不确定性 | 文献核查、定量审计、复现、评审、基金 |
| 6 | 规范化层 | 多种格式转换为一个规范对象 | BibTeX/RIS/CSL-JSON、CSV、单位、统计、元数据、学习材料 |
| 7 | 约束编译器 | 自然语言规则转为可执行检查 | 期刊指南、PRISMA、NIH 表单、学位论文模板、实验 SOP |
| 8 | 覆盖图 | 记录已检查什么、未检查什么、什么是未知 | 文献空白、系统综述、复现、知识图谱 |
| 9 | 检索与再浮现 | 在正确语境与时机把旧信息重新取出 | 阅读笔记、失败实验、旧分析、卡片 |
| 10 | 跨产物连接器 | 连接论文、论断、表格、代码、数据集、笔记与实验 | 整条科研链 |
| 11 | 确定性校验器 | 凡可计算或可规则检查者，绝不让模型凭感觉判断 | 数值、元数据、格式、哈希、schema、统计 |
| 12 | 不确定队列 | 自动化无法确定的事项进入显式人工队列 | 模糊去重、引文支持、定性编码、身份冲突 |
| 13 | 事件监视器 | 对对象未来状态做差异，只报告真实变化 | 撤稿、新论文、数据集发布、指南更新、依赖断裂 |
| 14 | 自适应练习引擎 | 按失败类型决定下一次学习行为，而非统一复习 | 间隔重复、证明、计算、语言、概念辨析 |

## 三、Research Object 模型

各技能作为同一结构的不同视图操作研究对象。

```
Research Object
  ├── Identity
  ├── State
  ├── Lineage
  ├── Evidence
  ├── Constraints
  ├── Coverage
  └── Events
```

示例：一篇 Paper 携带身份（DOI、arXiv、PMID、OpenAlex）、版本（预印本到录用稿到正式版到更正）、证据（元数据、全文、计算）、关系（引用、矛盾、复现）、产物（补充材料、代码、数据集）与事件（撤稿、更正、新引文）。一个 Dataset 携带身份、版本、schema、单位、清洗谱系、排除项与衍生产物。同一骨架覆盖学习中的 Concept：规范含义、前置知识、易混概念、例证、证据、学习者状态与错误历史。

## 四、四平面

仓库未来的能力空间按四平面组织，共享原语层。

- A 证据平面：身份、谱系、引文核验、矛盾。
- B 过程平面：协议、工作流、状态、差异、复现、决策历史。
- C 生产平面：计算、写作、评审、基金、系统综述、投稿。
- D 学习平面：前置知识、提取、错误分类、反馈、迁移、遗忘。

此处记录一项决策：学习平面是独立项目。它与研究生产共享原语，但与现有技能集零重叠；并入本仓库会稀释 tap 的身份语义。合理的归宿是独立的 hermes-learning-skills 仓库，或 Family HF 的学习 Zone。

## 五、候选方向

六个方向作为后续各轮候选，按痛点覆盖广度与既有资产的衔接度排序。

1. 论断-证据图：横跨阅读、写作、评审、撤稿与系统综述，直接消费 AcademicEvidenceReceipt。
2. 研究对象身份与谱系：几乎所有版本、重复与来源问题的根，升级 CanonicalWork 与回执 schema。
3. 方法与补充材料提取器：高频高痛、现有工具普遍薄弱；确定性提取方法谱系与补充材料交叉引用。
4. 约束编译器：一套机制覆盖期刊、基金、学位论文与报告规范；取规则、编约束、审产物、引确切指令。
5. 决策与负结果台账：长尾记录，长期价值异常高，是候选里实现量最小的一项。
6. 学习错误分类与自适应练习：归入独立学习项目，本仓库不实施。

## 六、阶段一：因子分解矩阵

任何新技能动工之前，候选选择先落在测量上。阶段一是确定性任务：把痛点图集每条映射到其触发的原语，统计每原语与每方向的覆盖杠杆。

- 输入：痛点图集条目（中英两版保持同步）。
- 映射：每条可映射到一个或多个原语，每条映射附一行理由。
- 输出：机器可读矩阵（docs/factor-matrix.json 或等价文件）、覆盖表与方向排序建议。
- 验收：矩阵入库；覆盖表呈现在研究计划中；排序建议是证据，不是对人类选型决定的替代。

矩阵度量哪些原语吸收枚举摩擦的最大份额，以可记录、可修订的映射替代对下一轮选型的直觉。

## 七、设计纪律

仓库延续 1.3 一轮建立的纪律。

- 确定性核心优先：凡可计算或可规则检查者，实现为带测试的纯函数，绝不用模型判断。
- 显式来源证据：每个结论携带来源、查询时间与覆盖范围。
- 有界模型判断：模型仅用于真正需要语言理解的任务，输出记录为候选，不记录为裁决。
- 不确定队列：无法裁决的事项进入显式人工队列，自动化不得静默处置。
- 处处回执：下游技能消费机器可读回执，不复述前一阶段的结论。
- 禁止主观打分：支持判断取类别值（supported、contradicted、unverifiable、out of scope），不合成任何数值质量分。

这个结构是把 PDF 丢给模型求分析的替代方案。仓库的质量差异来自确定性核心与回执，不来自更大的模型。

## 八、后续各轮验收条件

- 每个方向一个 PR，不做巨型合并。
- 新代码确定性优先；涉及模型的代码隔离并标注。
- 测试覆盖新代码及其回归面；全套须本地与 CI 通过。
- SLL 凭证文件零改动；任何 schema 或回执变更须保持历史记录完好。
- 文档两语版在合并前更新；新增定量论断先核源。

## 九、与其他项目的关系

原语层与 THM、Family HF 的证据与谱系思想有意重叠，但本仓库保持自身边界：研究对象上的小型确定性技能，不设运行时、不做记忆架构、不建世界模型。不从那些项目导入任何组件，也不要求任何依赖。
